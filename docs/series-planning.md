# 系列规划 —— 排期、选题与脱敏

录完第一期才发现「下一期讲什么」已经来不及想了？
这个文件解决**多期**视频的规划问题：一期能发 ≠ 系列能发。

---

## 1. 先问三个问题

| 问题 | 决定什么 |
|---|---|
| 这个 app 能讲出几个**独立**的问题？ | 决定期数。1 个问题 = 1 期，别硬凑 |
| 每个问题有没有「可自行验证的数字」？ | 决定能不能做。没数字的期 = 只能靠嘴 |
| 观众看完能自己动手复现吗？ | 决定形态。能复现 = 录屏 + 代码；不能 = 只能讲架构 |

**期数宁少勿多。** 5 期讲透 > 15 期凑数 —— 后者每一期都在稀释前面的信任。

---

## 2. 一期的骨架（照抄这个结构）

```
标题（反常识钩子 + 具体对象）
  → 开场（这是什么 + 为什么值得看 + 边界声明）
  → 问题（一个具体到能复现的场景）
  → 实操（屏幕上真的做一遍）
  → 数字（可自行验证的结果）
  → 收束（边界 + 预告）
```

**边界声明必须放在开场**，不是结尾。原因：观众在开头决定要不要看，把「全程合成数据」放在结尾等于骗点击。

---

## 3. 选题从哪来 —— 三个已验证的来源

| 来源 | 怎么找 | 注意 |
|---|---|---|
| **代码里的诚实边界** | 引擎源码注释 / 报错文案 | `grep -n "还没做\|不支持\|需要限价" <你的主模块>.py` |
| **方法论/踩坑** | 你的笔记库（研究/教训/决策分区） | ⚠ **必须先脱敏** —— 见 §6 |
| **真实事故** | 上线后被用户/同事指出的问题 | 最有价值，因为它是真的 |

### 🚨 来源二最容易出事

你的笔记库里可能写着**绝对路径、域名、profile 名、真实数字**。
直接拿来当素材 = 一期视频泄漏整个工作环境。

**实测教训**：规划「成交时点」这一期时，先 grep 到一条含本机绝对路径的笔记，
差点就按它写文案。后来发现真正的实现细节在**另一个 agent 的 skill 里** ——
两边口径不一致，按错的那个写，整期内容都是错的。

**动手前必做三步**：
```bash
# ① 确认实现真在哪 —— 别假设在你自己项目里
grep -rn "还没做\|口径\|成交" <dir> --include='*.py' | head -20

# ② 确认搜索真的生效了 —— 空结果可能是过滤器写错
grep -rn "关键词" <dir>/                      # 不加 --include
grep -rn "关键词" <file>                      # 直接打文件
grep -rn "关键词" <dir> 2>/dev/null | head -20

# ③ 确认不是同名符号 —— `fill` 会抢先匹配 `zfill`
grep -n "关键词\|fill" f.py
```

### 🚨 差值反推法（很好用）

两个数对不上时，**差值 ÷ 笔数 ÷ 乘数**，看能否整除成「每笔 X 元」。
整除 → 立刻定位到某个具体假设（如「昨日表未扣 N 跳成本」）。

同类可讲的方法论还有：**账本自洽式**
`期末 == 初始 + Σ差额 − Σ费用`（实测差 0.01 元即通过）。

## 4. 标题怎么起 —— 反常识 + 具体对象

| 类型 | 例子 |
|---|---|
| ✅ 反常识钩子 | 「回测显示 3%，实盘只有 1.5%，差的那一半藏在哪」 |
| ✅ 反常识钩子 | 「连续 K 线可能是假的」 |
| ❌ 原理剖析 | 「深度解析事件驱动引擎原理」 |
| ❌ 平铺直叙 | 「第二期：数据管道介绍」 |

**规律**：钩子必须**带一个具体数字或具体对象**。「原理」型标题没人点。

### 标题天然要偏工程

选题本身如果偏工程，标题天然就安全：

| 选题 | 工程语言标题 |
|---|---|
| 讲成交时点 | 「事件驱动引擎的成交时点」 |
| 讲连续序列拼接 | 「连续序列的拼接规则」 |
| 讲因子计算 | 「因子计算管线怎么写」 |

---

## 5. 一期必须自洽的三件事

```
① 标题承诺的数字  ==  画面里出现的数字  ==  旁白念的数字
```

任何一个对不上，观众会认为你在编。

**最强的自证形式**（强烈推荐）：
> 让观众**自己算一遍**，得到和你一样的数字。

这一步做到，评论区会自己变成你的质检团队。

---

## 6. 🚨 脱敏铁律（选期阶段就要做）

**绝不能出现**：策略名 · 参数（阈值/百分比/止损）· 对象/编号代码 ·
真实域名/路径 · 账户信息 · 业绩数字 · 任何内部标识

### ⚠️ 规划文档本身也要脱敏

写在笔记库里的选题表可能带真实名称、真实数字、真实路径。
**截图传播**会让它们绕过所有成片级脱敏。

**公开对象名（公开的商品名等）≠ 策略泄漏** ——
但**参数 + 公开名同时出现 = 策略泄漏**（因为参数是私密的）。

---

## 7. 规划表模板

```markdown
| 期 | 标题 | 主题 | 素材来源 | 状态 |
|----|------|------|----------|------|
| EP1 | 手搓研究终端：数据管道到引擎 | 总览 | 全流程实操 | ✅ 已交付 |
| EP2 | 回测 3%，实盘 1.5%，差的一半藏在哪 | 成交假设一致性 | 单项页 vs 组合页对照 | ⏳ |
| EP3 | 连续 K 线可能是假的 | 序列拼接 | 拼接规范文档 | ⏳ |
```

**素材来源列必须写具体文件/页面** —— 写「查一下」等于没规划。

### 规划决策要留痕

```
① 做成交时点  ② 允许公开对象名  ③ 不做短视频平台  ④ EP8 不提前
```

把「已决定的事」写下来，下次别再问一遍。

---

## 8. 常见翻车

| 症状 | 根因 |
|---|---|
| 选题里塞真实业绩数字 | 脱敏铁律 —— 标题也会被截图传播 |
| 每一期都在讲同一件事 | 选题没拆开 —— 一个 app 有一堆独立问题 |
| 素材来源写「查一下」 | 规划不落地 —— 录的时候才发现没素材 |
| 计划里的数字和成片对不上 | 没有第 5 节的三方自洽检查 |
| 排期越排越密 | 期数没砍 —— 5 期讲透 > 15 期凑数 |

---

## 9. 活文档

规划文档应该是**活文档**，不是一次性文件。放在你的笔记库决策分区，每期交付后更新状态。

```
<你的笔记库>/30-决策/视频系列规划-<项目名>-<日期>.md
```

⚠ 放在笔记库里的规划文档**也要脱敏** —— 见 §6。

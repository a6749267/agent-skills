# 字幕配方 —— 切句 / 排版 / 烧录 / 验收

## 一、时间轴：ASR 强制对齐是唯一正确来源

**按字数摊时间是猜的** —— TTS 语速不均匀（停顿/语速/句长都不同），每段偏 0.3~1.5s，
累积到片尾能偏好几秒。观众看到的就是「字幕比人声慢半拍」。

### 对齐轴的三个铁律

| 铁律 | 为什么 |
|---|---|
| **时间取 ASR，文字取脚本原文** | ASR 中文同音字错很多：终端→中端、这一屏→这一瓶、换月→换约 |
| **绝不用 ASR 的识别文本当字幕** | 同上，错字会直接显示给观众 |
| **对齐轴里没有标点** | 切句必须用脚本原文的标点，再映射回对齐轴 |

```bash
python scripts/subtitle_post.py --align align.json --script script.json ...
```

## 二、断句：标点优先于长度

### 硬折会产生的视觉重复

> 「先说清楚：它不是一个成品软件，是一个模块一个模块搭起来的。」

按 20 字硬折 → 「…是一个模块」/「一个模块搭起来的。」
→ 观众看到「一个模块」出现两次，像出 bug。

### 算法

1. 先按**句末标点**（`。！？；…`）断
2. 长句再按**软标点**（`，、：,`）断
3. 每段尽量 ≤ `max_chars`（默认 20）
4. 单条排两行时：**在标点候选里选让最长行最短的那个**，只要最长行 ≤ `max_chars × 1.25` 就接受
5. 标点实在不满足 → 才硬折（兜底）

### 为什么是「最长行最短」而不是「离中点最近」

四个标点的句子，离中点最近的未必让两行均衡。
目标是**可读性**（两行长度接近），不是"从中间切"。

### 阈值

| 参数 | 值 | 说明 |
|---|---|---|
| `max_chars` | 20 | 单行字数 |
| `max_lines` | 2 | 一条字幕最多两行 |
| `longest_ratio` | 1.25 | 最长行可超出 max_chars 的比例 |

1920 宽 + 44px 字体下，25 汉字约 1100px，放得下。长度约束是为了**可读性**不是宽度。

## 三、字体：三个静默失败点

### ① 路径传错类型 → 满屏豆腐块，零报错

```python
# ❌ F 其实是函数
ImageFont.truetype(F, 25)     # AttributeError
except: return ImageFont.load_default()   # 被吞掉 → 满屏缺字方框
```

**解法**：断言 + 失败即报错退出。
```bash
python scripts/subtitle_post.py --font-check
```

### ② `.ttc` 的 index 陷阱

| 字体 | index 0 | index 1 |
|---|---|---|
| `STHeiti Medium.ttc` | Heiti **TC**（繁体） | Heiti **SC**（简体） |
| `Menlo.ttc` | Regular | Bold |

→ 用繁体字形画简体字，部分字形不对。
→ `.ttc` 必须显式指定 index，且**不同字体不同**。

### ③ 等宽英文体不含汉字

`Menlo.ttc` 只有拉丁字形 → 拿它画中文全是豆腐块。
→ 中文文本必须用中文字体。

### 渲染参数

| 项 | 值 | 说明 |
|---|---|---|
| 字号 | 44px（正文）/ 26–30px（小字） | 26 以下在手机端看不清 |
| 行高 | `font_size × 1.35` | |
| 底部边距 | 60px | 平台会裁底部，留足 |
| 描边 | 1~2px | 白字在深底上本就有对比，过重会显糊 |
| 居中 | 按 textbbox 实测宽度 | 不要用 `len × 字宽` 估 |

## 四、烧录

### 必须在拼片阶段烧，不能成片后再烧

二次编码会把顶栏小字压糊 → 连累验收读不出数字。

### 用 overlay，不用 subtitles 滤镜

Homebrew 的 ffmpeg 默认**不编译 libass** → `subtitles` 滤镜报 `No option name near 'xxx.ass'`。
`overlay` 是内置滤镜一定有。

### 逐条 enable 区间

```python
f"[{cur}][{i}:v]overlay=0:0:enable='between(t,{st:.3f},{en:.3f})'[{nxt}]"
```
⚠ `enable` 用的是**输出时间轴**（= 绝对时间）→ 直接用 cue 的绝对秒数。

## 五、验收：覆盖率要排除四种区间

### 🚨 只排除 title_card 会误判

段尾静音尾巴：段落视频比旁白长，旁白说完后画面还在但没字幕 —— **设计如此**。

必须排除：
1. `title_card`（章节卡故意无字幕）
2. `intro`（片头动画）
3. `outro`（片尾动画）
4. **段尾静音尾巴**（段落末尾 0.6s）

### 判据

覆盖率 ≥ **90%** 算合格。低于则说明字幕真的没进成片。

### 三道必查

```bash
# ① 视频流必须只有 1 条（有字幕时 map 了原片+字幕片 = 两条 = 播放器放第一条 = 白烧）
ffprobe -v error -select_streams v -show_entries stream=index -of csv=p=0 final.mp4

# ② 抽帧裁字幕区，交给视觉模型 OCR，与期望值比对
#    (macOS Vision 读不了细条裁剪图，必须用更强的视觉模型)

# ③ 覆盖率检测
python scripts/subtitle_post.py --align align.json --script script.json \
    --timeline timeline.json --video final.mp4 --verify-only
```

## 六、常见问题

| 症状 | 根因 | 解法 |
|---|---|---|
| 字幕比人声慢半拍 | 时间按字数摊 | ASR 强制对齐 |
| 字幕断句怪 / 看起来重复 | 按字数硬折 | 标点优先 + 让最长行最短 |
| 满屏豆腐块 | 字体路径传错类型静默回落 | 断言 str + `--font-check` |
| 繁体字形 / 部分字不对 | `.ttc` 没指定 index | 显式 index（Heiti=1） |
| 字幕挤成一行 | 返回字符串没转行列表 | 转成行列表 |
| 验收误报「成片没字幕」 | 没排除段尾静音尾巴 | 排除四种区间 |
| 字幕被动态界面遮挡 | 动态元素没避开字幕区 | 字幕区留安全带 |
| 顶部小字读不出来 | 成片后再烧字幕 | 拼片阶段烧 |
| 字幕在手机端看不清 | 字号太小 | ≥26px |
| 底部字幕被平台裁 | 边距不足 | 上移 + 留足边距 |

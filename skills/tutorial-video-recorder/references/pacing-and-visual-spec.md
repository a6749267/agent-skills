# 节奏与画面规范（录屏类教程视频）

> 录屏天生是**死画面**：界面静止 20 秒不动一个像素 → 观众 3 秒划走。
> 这份文档把「画面闷」变成**可测数字**，并给出四个参考视频验证过的解法。

---

## 1. 为什么录屏必须做视觉层

用帧差量化（`scripts/pace.py`）实测同类视频：

| 指标 | 技术开源视频 89s | ComfyUI 整合包 1210s | 改造前成片 187s |
|---|---|---|---|
| 变化强度（帧差均值） | 19.35 | 6.21 | **0.88** |
| 变化帧/分钟 | 54.6 | 45.2 | **14.1** |
| 最长静止段 | 几乎没有 | 少 | **15s** |
| 静止画面占比 | 低 | 低 | **76.3%** |
| 大标题压屏 | 每段都有 | 章节标题 | **0** |
| 画面框选标注 | 有 | 有 | **0** |
| 局部特写 | 有 | 有 | **0** |

改造后：强度 **4.77** / 59.1 帧每分 / 最长静止 **1s** / 静止占比 **1.5%**。

**「感觉有点闷」说不出差在哪 → 帧差能给出硬指标。** 别凭感觉判断节奏。

## 2. 四个参考视频的共通解法（全部照抄）

### 2.1 大标题压屏（chapter card）

参考视频的招牌手法：**模糊底 + 超大粗衬线标题 + 荧光色关键词**。

| 要素 | 做法 |
|---|---|
| 底图 | **该段自己的画面**（抽帧 → 高斯模糊 → 压暗 55% → 去色 45%）→ 观众看得出延续性，不会像突然黑屏 |
| 标题字体 | **粗衬线体** `Songti.ttc` index 0/1（Songti SC Black/Bold）——参考视频主标题就是这个调性 |
| 字号 | 120px（1920 宽下约 6 字/行） |
| 关键词 | **只给核心词染荧光色**，其余白色。颜色即层级；整句都上色 → 糊 |
| 模块角标 | 圆角胶囊，荧光色底 + 深色字，**比主标题小**（别抢注意力） |
| 下划线 | 荧光色，宽度 ≈ 标题宽 58%，**承托整行标题**（短到 34% 像装饰不像承托） |
| 副标题 | 白色 42px，**不要重复模块名**（角标已写「数据」，副标题再写「数据模块…」显啰嗦） |
| 时长 | 1.9s（1.5~2.2s 区间），淡入淡出 0.3s，**静音** |

**位置在段落之前，不占旁白时间** → 字幕覆盖率不受影响，段落内每帧仍有字幕。

**标题卡是故意没有字幕的** → 验收算覆盖率时必须排除这些区间，否则会**误报「成片没字幕」**。

🚨 **卡片时长必须帧对齐**：`frames = round(duration*fps)`，视频 `-frames:v frames`、
音频 `-t frames/fps`。容器时长 ≠ 帧数/fps 会留**半帧空洞** → concat 按容器时长算偏移
→ PTS 出现 0.08s 跳变 → 容器推断成 50fps（实际 25）→ 播放器可能错帧。
**见 pitfalls G14。**

### 2.2 荧光色关键词（只染核心词）

```json
{"title": "防自己骗自己", "keyword": "骗自己", "module": "历史记录"}
```

⚠ **keyword 必须是 title 的子串**，否则不染色（静默失效）。

### 2.3 画面框选标注（highlight box）

- **框要贴着目标**，别太空（框大一圈 → 观众以为框里所有东西都重要）
- 圆角描边 stroke=4 + **四角轻微加粗**（stroke+2 即可；装饰过重 → 像儿童贴纸）
- 标签牌离框留 gap，**位置自动避让推镜安全区**（见 2.5）
- **框必须在推镜之前 overlay** → 框跟着内容一起被推，不会错位
- 定位不到目标 → **fail loud 报错退出**，绝不静默跳过

**模块配色**（一个模块一个颜色，观众靠颜色定位章节）：

| 模块 | 色 | 模块 | 色 |
|---|---|---|---|
| 工作台 | `#00e5ff` 青 | 历史记录 | `#f59e0b` 橙 |
| 数据 | `#3b82f6` 蓝 | 工具面板 | `#a855f7` 紫 |
| 实验面板 | `#ff2d55` 玫红 | 执行台 | `#22c55e` 绿 |

⚠ **验收时别按「应该是青色」去找框** —— 框是按章节着色的。

### 2.4 推镜（kill the dead frame）

```
scale=iw*1.06:ih*1.06, crop=1920:1080:x='57.5+57.5*sin(t/9)':y='32+32*sin(t/6.6+1.1)'
```

- **不要用 `zoompan`** —— d/fps/时长三者关系极易错（实测把 20s 段拉成 60s）
- `crop` 的 x/y 支持 `t` 表达式 → 时长天然正确
- zoom 别超过 1.15（边缘内容被裁 + 顶栏小字读不出来）

### 2.5 推镜安全区（**最容易漏**）

推镜 = 放大 Z 倍后裁一个 WxH 窗口漂移。原图坐标里只有
`y ∈ [H*(Z-1)/Z, H/Z]` 这一带**任何时刻都在画面内**。

**边距 = `H*(Z-1)/Z`** —— 不是 `H*(Z-1)/2`（那是放大图上的像素，换算回原图要除以 Z）。

**症状**：顶栏数字（y≈97）的框，标签牌默认放框上方（y≈46）→ 落在安全区外
→ 推镜一漂就被裁掉 → 观众看到一个**没有标签的框**。

**解法**：标签牌按 **上→下→右→左** 顺序挑第一个完整落在安全区里的位置。

## 3. 目标区间（录屏类）

| 指标 | 目标 | 说明 |
|---|---|---|
| 变化强度（帧差均值） | ≥ 3.0 | 参考视频 6.2~19.4 |
| 变化帧/分钟 | ≥ 30 | 参考视频 45~55 |
| 最长静止段 | ≤ 6s | 观众划走的时点 |
| 静止画面占比 | ≤ 25% | 死画面总量 |

上限由「闪得让人晕」决定，不设死线。

```bash
python scripts/pace.py 成片.mp4                      # 单个体检
python scripts/pace.py 改造前.mp4 改造后.mp4 --compare  # 对比
```

## 4. 验收视觉层（客观，不靠肉眼）

肉眼在缩略拼图上看不清框准不准。**决定性做法**：

1. 在成片里按**精确颜色**（如 `#00e5ff`，紧公差）检出高亮框描边像素 → 得到框的实际 bbox
2. 裁框**内部**区域 → 放大 2× → OCR
3. 框内**必须**读到目标文字

⚠ **不要用「饱和度高」筛框** —— UI 自身的涨跌红绿会被一起选中，得到整个画面。

⚠ OCR 读小字**必须放大 2×**（原生 1920 下顶栏数字会读成乱码，见 pitfalls G8）。

## 5. 参考视频取样手法（可复用）

要从 B 站等对标视频提取节奏/画面规律：

```bash
# 1. 下载（1080p 足够）
yt-dlp -f "bestvideo[height<=1080][ext=mp4]+bestaudio[ext=m4a]/best[height<=1080]" \
       --merge-output-format mp4 -o ref.mp4 "<url>"

# 2. 硬切点
ffmpeg -i ref.mp4 -filter:v "select='gt(scene,0.2)',metadata=print:file=-" -an -f null -

# 3. 帧差时间线 → 变化强度 / 变化帧每分 / 最长静止段
#    (见 scripts/pace.py)

# 4. 抽 1fps 帧拼 contact sheet → 一次看完整个视频的画面语言
```

**接触表（contact sheet）**：把关键帧缩略拼成一张图，一次 vision 调用看完整片风格，
比逐帧调用便宜几十倍。但**缩略图看不清小字** → 结论只能用于「构图/配色/密度」，
精确文字必须回原分辨率裁切再看。

## A. 会让成片「根本不合格」的坑

### A1. 🚨 验收必须针对**交付物本身**（§25）
**症状**：验证脚本报「10/10 模块正常、零泄漏」，但用户看完成片直接判
「你那张只是网站的首页介绍页面，没有登陆进去」。
**根因**：`verify_synth.py` 和 `record4.py` 是两套独立脚本 —— 不同 profile、
不同拦截配置、不同登录路径。verify 通过**完全不代表**成片通过。
**解法**：验收脚本必须吃交付的 mp4。对成片抽帧做全片 OCR 盲扫 + 关键帧判读。
DOM 判定只能用来**定位哪一段有问题**，不能替代这两项。

### A2. 🚨 新账号天然是空的 → 录出来像「没登录」（§18/§26）
**症状**：10 个模块里 6 个渲染成「暂无 / 还没有运行中的任务」。观众视角就是空壳。
**根因**：新注册的演示账号零记录零订单零清单零任务。
**解法**：**给演示账号灌合成业务数据**（写数据库，不是靠 API 拦截）。
拦截只能造「空状态看起来有骨架」，灌库才能造「有人在用的系统」。
最小集：明细 3 / 订单 5 / 流水 6 / 清单 5 / 任务 3 + 趋势曲线 / 分组 2。
只写自己那一个 user_id。

### A3. 🚨 验证脚本自己**路径不一致** —— 比 A1 更隐蔽（§34）
**症状**：verify 报「零真实数据」，但两边结论会分叉。
**根因**：`verify_synth.py` import 了清洗模块但 `on_route` 里**根本没用**（少一个分支）→ 报「零泄漏」是侥幸。
**解法**：录制和验收**抽成公共模块**，两边 import 同一个 `make_handler()`。
自查：`grep -c is_business` 两边都 ≥2（import + 使用），=1 就是没接上。

### A4. 🚨 后端把汇总字段硬编码 0（§33）
**症状**：同一画面里顶栏 `+0.00`、明细行 `−1200.00`，观众一眼看穿。
**根因**：后端 `account_svc.py:301` 硬编码 0，而前端「概览卡」用数据 `last_price` 自己算。
**解法**（录制层，不改生产代码）：拦汇总接口，用**同一套数据**重算
unrealized/today/subtotal/available/usage_rate。
⚠ 另算一套价格仍对不上。
⚠ 单元测试通过 ≠ 路由生效 → 必须在浏览器里断言 API before/after 真的变了。

### A5. 🚨 任务卡片数值恒为 +0.00（§36）
**症状**：工作台「分组概览」里每条都是 `+0.00`，「累计差额」也是 0。
**根因（两个叠加，都在后端）**：
- `get_task_record_pnl` 用 `Record.task_id == task_id` **精确隔离**，
  灌库时明细的 `task_id` 是 NULL → `NULL == uuid` 永不匹配 → `record_*` 全空
- `resolve_last_price()` 从 Redis 取真实数据，合成数据只在浏览器侧 → 取不到
  → `last = avg` → 差额恒 0
- 前端要求 `direction && qty>0 && avg!=null` 才返回 `hasRecord:true`，否则 `pnl=0`
**解法**（录制层）：拦该接口，用**前端同一套公式**补
`record_direction/qty/unit_price/last_price/unrealized_pnl`，
`last_price` 必须取**和画面渲染同一个值**。
⚠ 别指望灌趋势曲线能救 —— 前端根本不用它算卡片数值。
**自检**：卡片数值应与明细逐笔差额**完全相等**。

### A6. 🚨 数字必须用原生 OCR 判读（§40）—— **最贵的坑**
**症状**：vision 读缩略拼图，把 `−1200.00` 读成 **`−1400.00`**、
把 `996,000.26` 读成 **`996,200.24`**，然后**自己算出**
「三笔之和 −1600.00 与顶栏 −1400.00 不一致」并质疑数据 —— **画面其实是对的**。
**根因**：低分辨率下字形糊，vision 会读错；它还会**自己算加法**并把错误结论当发现。
**解法**：
- 成片金额一律走 **macOS 原生 Vision OCR**，抽帧时放大（1920×1080 → 3840×2160）
- vision 只用来判断「模块在不在 / 是不是空态」，**不让它读金额**
- 交叉验证：OCR 读数 + **源头算式**（DB 明细 × 单价 × 数量）双向对上才算数
- ⚠ **假不一致比真不一致更贵** —— 会让人去改本来正确的数据
**症状识别**：vision 说「这几笔加起来和总额不一致」时，**先怀疑它自己读错数字**。

### A7. 🚨 全片 OCR，不是抽查（§14/§17）
**症状**：抽查 5 帧都干净 → 判定「零泄漏」→ 第 7 秒那帧有真实编号。
**根因**：抽查不构成证明。
**解法**：全片 @2fps 抽帧逐帧 OCR。
⚠ **「扫描结果是干净的」可能意味着「什么都没扫到」** —— 两种失败看起来都像成功：
- 假阳性：把候选禁用词写进 prompt → 模型把你的清单**背回来**（问「有没有 ab2701」它答「有 ab2701」）
- 假阴性：思维链把 `max_tokens` 吃光 → 正文 0 字 → 报「无命中」
**规矩**：① prompt 里**一个候选词都不给**，只让它转录；② 断言每帧 OCR 长度 > 阈值；
③ **用不依赖模型的方法交叉验证**（源头 payload 字符串证明 + 边缘密度离群检测）。
🚨 **别用 MiniMax 做纯 OCR** → 用 macOS 原生 Vision（本地、免费、无限速、中文强）。

### A8. 🚨 域名/前端资源会被真实浏览器**绕过**（§11）
**症状**：拦截规则写了，但一个都没生效。
**根因**：Next.js 图片走优化器，实际请求是
`/_next/image?url=%2Fshowcase%2F08-market.png&w=128&q=75` —— **按原始路径匹配会一个都拦不到**。
**解法**：先探测真实 URL：
```js
Array.from(document.querySelectorAll('img')).map(i => i.currentSrc || i.src)
```
⚠ **拦截后要数命中数**：0 命中 = 匹配规则错了，不是「没有敏感资源」。

### A9. 🚨 浏览器磁盘缓存让拦截**完全失效**（§3）
**症状**：第一次录像是合成的，第二次录出来还是第一次的旧数据。
**根因**：bundle 被缓存了。
**解法**：`--disable-http-cache --disk-cache-size=1` + 每段用全新 profile。

### A10. 🚨 登录态注入的三个坑（§19/§20/§28）
- **`/api/users/me` 的 id 必须是真实 user_id** —— 换成全零 UUID → 前端对不上账 →
  业务接口全 401 → 前端清 token 跳 `/login`。**只脱敏显示字段，id 不能动。**
- **优先「浏览器里 fetch 拿 token → 注入 localStorage」** —— 前端表单在无头/拦截环境下
  **偶发不提交**（连请求都不发，静默失败）；裸 curl 被 Cloudflare 挡（`error code: 1010`）
  → 必须在浏览器上下文里 `pg.evaluate(fetch(...))`
- **每段新 profile 走登录页不稳** → 录制时直接注入 localStorage 跳过登录页

## B. 会让数据泄漏的坑

### B1. 🚨 DOM 级脱敏刷不到像素里的东西（§10）
**症状**：Playwright 遍历文本节点替换敏感词，替换计数 596 处，但**截图里照样残留**。
**根因**：金额、对象名、编号是 `<img>` 里烘死的像素。
**解法**：**凡是「从真实产品截图取材」的视频帧/宣传图，DOM 脱敏一律无效** →
正确做法是**画合成素材**，别去修真实截图。
（本管线走的是「真前端 + 合成数据」，天然没有这个问题。）

### B2. 🚨 合成码映射表会自己撞回真实前缀（§12/§19）
**症状**：映射表越写越长，尾部踩回真前缀（`sr→sa`、`bc→sc`，而 `sa`=硅、`sc`=原油）。
**解法**：整个编号 token → 合法合成编号，**不要一对一映射**。
⚠ 构造时**主动检查**：`SyntheticConfig(prefixes=...)` 撞了直接抛异常。

### B3. 🚨 「4 位数字」≠「编号」（§13/§20）
**症状**：真站文案「最长示例对象甲 7000+ 项」被洗成「最长合成对象C10+ 项」。
**根因**：没有编号形状守卫。
**解法**：编号形状 = `2x` 年 + `01`~`12` 序号。**守卫要同时用在 scrubber 和判定脚本两边。**
⚠ 名字后面的数字不是编号形状时，**只能换名字，不能动数字**。

### B4. 🚨 OCR 会吞掉首字母 → 合成码被误判成真编号（§14/§21）
**症状**：`qc2710`→`c2710`、`qa2701`→`a2701`。**单字母前缀恰好全是真实前缀**
（你的 app 里那些单字母代码：a/c/m/y/p/b/i/j…）→ 47 帧假阳性。
**解法**：伪影排除 —— 单字母前缀命中 + 同帧存在合成码 → 丢弃。**人工用原分辨率复核。**

### B5. 🚨 vision 读缩略图会把合成码误读成真前缀（§35）
**症状**：`qa2701` 在缩略拼图上被读成 `cu2701` 和 `WH705`（不存在的编号）。
**解法**：判定泄漏必须用**原分辨率裁剪**（放大≥2倍 + 限定区域 + 明确问「首字母是 q 还是 c」）。
缩略图只能用来**定位可疑段落**。
**假报警比漏报更贵** —— 会让人改本来正确的代码。

### B6. 🚨 裸名称要单独一条规则（§12）
**症状**：对象中文名（玻璃/黄金/塑料/纯碱/棉纱/苹果）从截图里漏了出去。
**根因**：只抓「名称+序号」「编号代码」，漏了**光秃秃的对象中文名**。
**解法**：加「对象中文名」规则。因「黄金/苹果/塑料」都是常用词，
必须同行业出现该领域的上下文词才报。

### B7. 🚨 裸名称要单独一条规则 —— 自由文本字段最容易漏
**症状**：合成码替换了，但 `note` 字段里的「示例商品甲」还在。
**根因**：字段级清洗只处理了 `symbol`/`name` 这类**键名**，没处理**自由文本的值**。
**解法**：字符串先按编号形状替换，再替换名称（顺序反了会漏）。

### B8. 🚨 清洗层可能是**空转**的（§18）
**症状**：DOM 清洗层写 `new RegExp('...(\\\\d{4})...')`（Python raw string 里 4 个反斜杠），
JS 字符串解析后正则变成 `\\d` = 匹配「一个字面反斜杠+d」→ **编号清洗从来没生效过**。
全靠 bundle 层扛，所以整条链路「看起来是通的」。
**解法**：JS 源码里要 **2 个**反斜杠 `\\d` 才是正则 `\d`。
**自检**：别肉眼数反斜杠 → 单独断言 `new RegExp('(\\d{4})').test('ab2701')` 为 true。

### B9. 🚨 「金额必须全 0」是错的 —— 要按字段名判（§16/§23）
**症状**：把价格也清零 → 图表是空的 → 画面像坏了。
**根因**：混淆了两类字段。
**解法**：合成数据的**单价/数量本来就该非零**；
只有**盈亏/权益类**字段必须为 0，按字段名白名单判
（`balance`/`realized_pnl`/`unrealized_pnl`/`today_pnl`/`total_equity`… 等汇总类字段）。
⚠ Python 标识符不能含 `&`：`P&L_FIELDS` 被解析成 `P & L_FIELDS` → SyntaxError，写 `PNL_FIELDS`。
⚠ 色值 `#ef4444` 会被编号正则命中 → 排除前导 `#`。

### B10. 🚨 趋势曲线起点也是数字，也要归零（§16） <!-- leak-ok -->
`equity_series` 里 equity 起点是 100000 → 出现在图表纵轴上。哪怕「人人都有初始额度」，
按最严标准归零。

### B11. 🚨 真实看板的泄漏面比「业绩数字」大得多（§12）
实测扒一张真实数据图：17 个编号、每个对象的价格与涨跌幅、买卖盘口与挂单量、
MA5/MA10/MA20 数值、成交量、库存 —— **整个数据面**。
→ 承诺「安全抓取」之前先**枚举**这张图到底有什么，别只盯着 P&L 那一栏。

### B12. 🚨 边缘密度离群检测 —— 最便宜地定位可疑帧（§17）
真实数据表**文字密集**，空看板不密集。逐帧算边缘密度、只看**离群帧**：
```python
edge = sum(1 for y in range(0,h,3) for x in range(0,w-3,3)
           if abs(px[x,y]-px[x+3,y]) > 40)
```
实测 144 帧密度 3807–3834 全线平稳、无离群 → 时间轴上没藏数据表。
**这一步不用模型，成本极低。**

### B13. 🚨 证明「干净」要在数据源头做，不在像素层做（§15）
你已经用 `route.fulfill()` 换掉了 API 响应 → 那真正要证明的是
**「真实值有没有进到 payload 里」** —— 字符串搜索就能**穷尽**证明：
把真响应体里的所有敏感 token 逐个在 payload 里搜 → 必须 0 命中；
所有「像代码的字符串」必须都是你自己编的前缀；所有盈亏金额必须为 0。
**视觉扫描做不到这种穷尽证明。**

## C. 会让画面「对不上」的坑

### C1. 🚨 唯一约束可能不含区分维度（§37）
**症状**：灌第 2 个策略直接 `UniqueViolation`。
**根因**：`uq_group_equity_day = (account_id, snapshot_date)` **不分组** → 同账户同一天只能一行。
**解法**：多策略按 `i*45` 天错开 `snapshot_date`（`run_date` 同样要错开）。
⚠ 同类坑：`%s` 占位符与 SQL 里的 `%` 冲突 —— `name not like '%实盘%'` 写成字面量
会被 psycopg2 当占位符 → `IndexError: tuple index out of range`。
**含 `%` 的 LIKE 条件必须参数化传值**。

### C2. 🚨 前端数据快照是「不带参数」的全量接口（§31）
**症状**：明细页现价列全是 `--`。
**根因**：只返 1 个。
**解法**：adapter 要覆盖全量接口。
⚠ 生成列表别写 `for c in "ABCDEFGH"`（单字母！）→ symbol 变 `a2701` 丢前缀 → 前端查不到。
用两字母 `["QA","QB",…]`。

### C3. 🚨 灌完库后查「编号前缀 ↔ 名称」对应（§32）
**症状**：界面显示「qc2701 | 合成对象B01」，对不上。
**解法**：索引对齐，或**从 code 推导名字**。
同理流水 `flow_type` 必须用前端 `flowTypeLabel()` 认识的枚举
（claim/freeze/unfreeze/fee/open/close/settlement），用前端不认的值 → **裸露英文**。
**灌完库的必查项**：逐页 `inner_text` 抓 ① 裸露英文枚举 ② 编号与名称错位
③ 该有价格的地方是 `--`。**这三条靠截图看不出来。**

### C3a. 🚨🚨 unit_price 必须和 quotes() **自洽** —— 否则比例全错而"看起来正常"
**症状**：画面上金额是 +2480 / −2960 这种量级，比例完全失真，
但**每一个数字都存在、都不是 0、汇总也等于明细之和** → 检查项全过，肉眼看也像有数据。
**根因**：`unit_price` 抄了历史值（118.40/126.40/149.03），但 `quotes()` 生成的是另一套
（441.83/527.62/309.47）→ 差额 = (last−unit_price)×qty 自然爆炸。
**解法**：**反解** unit_price，让差额等于你要的数：
```python
last = qm[code]["unit_price"]
unit = last - target/(qty*mult)      # 方向 in
unit = last + target/(qty*mult)      # 方向 out
```
**自检**：算出三笔差额后，确认**量级合理**（单笔通常在总额的千分之几到百分之几），
别只看"有没有数字"。
⚠ 这是「换成你自己的 app 时最容易复制错的一处」—— adapter 模板里的 unit_price
必须跟着 quotes() 一起改，否则给别人的示例本身就是错的。

### C4. 🚨 合成数据要**可复跑**（§6）
**症状**：每次跑合成价格都变 → 录屏前后界面数字对不上。
**解法**：不能用 Python 内置 `hash()`（每进程随机）。用确定性哈希。

### C5. 🚨 灌数据库的六个坑（§21/§29）
① UUID 传 `str()`；② `offset` 是 SQL 保留字要加引号；③ 查 uuid 列用 `user_id::text=%s`；
④ 同名对象跨盘唯一要加后缀；⑤ 占位符数量对不上 → 用具名参数；
⑥ **⚠ `except: conn.rollback()` 会把整个事务回滚** —— 一条失败、前面几百行全撤，
脚本却打印「成功」→ **每步独立 commit，错误直接抛**。

### C6. 🚨 拦完业务接口还要放行（§30）
灌完库后**拦截层要放行业务接口**（account/records/orders/ledgers/list/…），
否则界面还是空的；但放行 = 真响应进画面 → 再加**字段级兜底**递归替换，双保险。

## D. 会让「音画/成片」出问题的坑

### D1. 🚨 音画对齐要用黑场标记，别用 `zoompan d=` 猜（§video-real-ui-pipeline §2）
**做法**：录制时每段片头插 2s 纯黑 → 合成时用 PIL 数中心区域纯黑像素占比
定位黑场结束点 → 旁白从那一刻开始播 → **像素级对齐**。
⚠ `blackdetect` 对深色主题**失效**（站点本身就是深色，纯黑分不出来）→ 必须自己数像素。

### D2. 🚨 ffmpeg 可能**没编译 libass** —— subtitles 滤镜根本不存在
**症状**：`ffmpeg -vf subtitles=xxx.ass` 报
`No option name near 'xxx.ass'` / `Error parsing a filter description`。
**陷阱**：三种路径转义写法（无引号 / 转义冒号 / 引号+转义）**报的是同一个错** ——
看起来像转义问题，其实是滤镜不存在，会一直调错方向。
**自检**：`ffmpeg -hide_banner -filters | grep -E "subtitles|drawtext"` 为空
+ `ffmpeg -version | grep enable-libass` 为空 → 就没有。
**解法**：**用 PIL 自己渲染字幕成 PNG，再用 `overlay` 滤镜贴上去**。
overlay 是内置滤镜一定有。字体渲染还更可控（描边、字号、位置随便调）。
**burn 的实现**：每条字幕渲染一张 PNG，然后
`[0:v][1:v]overlay=0:0:enable='between(t,a,b)'[v1];[v1][2:v]overlay=...`
一次 filter_complex 串起来，不要一条字幕调一次 ffmpeg（37 条 = 37 次进程，慢到不可用）。

### D2a. 🚨 字幕断句要在**标点处**断，不能按字数硬折
**症状**：「先说清楚：它不是一个成品软件，是一个模块一个模块搭起来的。」
按 20 字硬折 → 「…是一个模块」/「一个模块搭起来的。」→ **视觉上像重复了「一个模块」**。
**根因**：中文字幕要在标点处断；硬折会切在词中间。
**解法**：① 切句时在**每个逗号/顿号处**切（不设长度下限，可读性优先于条数）；
② 折行时找**离中点最近的标点**，中点前后都要看；
③ 合并过短碎片（避免「为什么？」孤零零一条）。
⚠ 有些句子内部**就是没有标点**（「回测图表那块我故意留空」）→ 任何算法都会硬断。
**这种情况要改文案**，加个逗号：「回测图表那块，我故意留空。」
→ 字幕断句不自然是**文案问题**，不要用算法硬凑。

### D2c. 🚨🚨🚨 字幕必须在**拼片阶段**烧, 不能成片后再烧
**症状**：加了字幕之后，验收读不出「−1,652.90」了 —— 而**无字幕版能读出**。
画面上数字明明还在。
**根因**：成片后再烧字幕 = **二次编码** → 整帧重压缩 → **顶栏那些小字被压糊**
（实测顶栏裁图的 md5 都变了）。字幕只画在底部，但二次编码影响**整帧**。
**解法**：在 compose 的**拼片阶段**就把字幕 overlay 进 `v{i}.mp4`，
后面 concat 和 loudnorm 都用 `-c:v copy`（不重编码）→ 顶栏像素与无字幕版**完全一致**。
**自检**：
```bash
ffmpeg -ss 12 -i 带字幕.mp4 -frames:v 1 -vf "crop=800:60:250:0" a.png
ffmpeg -ss 12 -i 无字幕.mp4 -frames:v 1 -vf "crop=800:60:250:0" b.png
md5 -q a.png b.png     # 必须相同
```
⚠ 连带坑：循环里别把变量叫 `dur` —— 会遮蔽模块级的 `dur()` 函数，
报 `UnboundLocalError: cannot access local variable 'dur'`。

### D2e. 🚨🚨🚨 字幕会被**静默跳过** —— 交付物根本没字幕，而所有验收都过
**症状**：交付的视频**完全没有字幕**，用户一句"视频没字幕啊"才发现。
**诡异之处**：规格正常、时长正常、响度正常、OCR 泄漏盲扫正常、
顶栏像素 md5 与无字幕版**完全一致** —— **所有自动化验收全过**。
**根因**：`script_path` 用了**相对路径**，且是相对 **CWD** 解析：
```python
script_path = pathlib.Path(cfg.get("script_path", "script.json"))
if sub_cfg.get("enabled", True) and script_path.exists():   # ← 找不到就跳过, 不报错!
```
归档目录里文案叫 `script4.json`，父目录才叫 `script.json`。
换个目录跑 compose → `script_path.exists()` 为 False → **字幕被整段丢弃**，
流程照跑成功，最后还打印「✅ 字幕已随拼片烧入」—— 实际上 `seg_cues` 是空的。
**解法**（三条一起上）：
```python
script_path = pathlib.Path(cfg.get("script_path", "script.json"))
if not script_path.is_absolute():
    script_path = pathlib.Path(a.config).resolve().parent / script_path   # 相对配置文件目录
if sub_cfg.get("enabled", True):
    if not script_path.exists():
        sys.exit("❌ 字幕已开启但找不到文案 ... —— 字幕必须烧进成片, 不能静默跳过")
```
**铁律**：任何"可选特性"的开关，**要么真的开，要么报错退出**，绝不能静默降级。
静默降级 = 交付物缺功能 + 验收全过 = 最难查的一类 bug。
⚠ 更隐蔽的变体：`seg_cues` 为空时那句「✅ 字幕已随拼片烧入」是**在 `if seg_cues:` 里**才打印的，
所以根本不会打印 —— 但流程仍然 0 退出成功。

### D2f. 🚨 有字幕时 `-map` 只能有一条视频流
**症状**：烧完字幕，播放器里**看不到字幕**（但 ffprobe 里明明有 overlay）。
**根因**：
```python
cmd += ["-map", "0:v:0", "-map", "1:a:0"]      # ← 原片
if pngs:
    cmd += ["-filter_complex", fc, "-map", f"[{prev}]"]   # ← 字幕片
```
两条视频流 → 播放器默认放**第一条**（无字幕那条）→ 白烧。
**解法**：有字幕时**只 map 滤镜输出**，无字幕才 map 原流：
```python
cmd += ["-map", "1:a:0"]
if pngs:
    cmd += ["-filter_complex", ";".join(fc), "-map", f"[{prev}]"]
else:
    cmd += ["-map", "0:v:0"]
```
**自检**：`ffprobe -v error -select_streams v -show_entries stream=index -of csv=p=0 成片.mp4`
→ 必须**只有 1 行**。

### D2g. ⚠ 字幕要铺满**整段**，最后一条吃到段尾
**症状**：段落末尾有 ~1 秒没字幕（每段 content = wav_dur + 0.9）。
**根因**：字幕时间轴按 `wav_dur`（旁白时长）分配，但视频片段长 `content`。
**解法**：按 `content` 分配，且**最后一条吃掉剩余时间**（`seg_d = seg_total - t`）。
实测：改之前 187 帧里 8 帧无字幕，改之后 4 帧（全是段落切换帧，正常）。

### D2d. ⚠ 数字判读要**整帧 + 区域裁剪**两种读法都做
**症状**：整帧放大能读出「−1,652.90」，但把顶栏裁成细条单独读就读不出；
反过来带字幕版整帧读不到。
**根因**：Vision OCR 的行聚类对输入布局敏感 —— 整帧和裁剪是两种不同的切分方式，各有盲区。
**解法**：两种都读，数字取**并集**。verify.py 已内置（`verify.amplify_crops` 配置裁剪区域）。

### D3. 🚨 命名/陈旧文件会**静默**污染下游（§38）
**症状**：整片用的是上一轮旧文件，**规格完全正常、看规格发现不了**。
**根因**：产出 `v00.mp4` 而下游读 `v{i}.mp4`（命名差一位）。
**解法**：命名逐字符统一 + **每个合成脚本开头清理上一版产物** + 产出后核对 mtime。

### D4. 🚨 响度必须实测（§39）
**症状**：成片 **−32.0 LUFS**（人声几乎听不见）。
**根因**：漏加 loudnorm 滤镜。
**解法**：产出后跑 `loudnorm=print_format=summary` 核对（目标 −16 LUFS）。

### D5. ⚠ ffmpeg 表达式的三个细节（§39）
- `pad` 要 pad 到 H(1920) 不是 VH
- `SRC_H = 1080*1080/1660`
- f-string 里 ffmpeg 表达式要真插值 `{(VH-SRC_H)//2}`，写 `(VH-{SRC_H})/2` 会被当字面量

### D5a. 🚨 concat demuxer 需要**绝对路径**
**症状**：`Error opening input file work/out/alist.txt` —— 文件明明生成了。
**根因**：concat 清单里写的是相对路径，ffmpeg 的工作目录不是你以为的那个。
**解法**：`alist.write_text(f"file '{p.resolve()}'\n")` + `-i str(alist.resolve())`。

### D5b. 🚨 `-af` 不能命名输出标签
**症状**：`Output with label 'a' does not exist in any defined filter graph, or was already used elsewhere.`
**根因**：`-af` 建的是隐式滤镜链，**没有可引用的标签**；`-map "[a]"` 找不到它。
**解法**：用 `-filter_complex "[0:a]loudnorm=...,aresample=44100[a]"` + `-map "[a]"`。

### D5c. ⚠ loudnorm 配置要分清「滤镜名」和「参数」
配置里存 `I=-16:TP=-1.5:LRA=11`（参数部分），拼滤镜链时必须补 `loudnorm=`：
- 漏了 → `[0:a]I=-16:TP=-1.5:LRA=11` → ffmpeg 直接报 filter 找不到
- 补两次 → `loudnorm=loudnorm=...` → 同样报错
**解法**：拼接前判断 `if not ln.startswith("loudnorm="): ln = "loudnorm=" + ln`。

### D5d. ⚠ loudnorm 的输出格式随 ffmpeg 版本变
**症状**：响度检测返回 `?`，看起来像"没测"，实际是格式没匹配上。
**根因**：新版输出 `Input Integrated:    -16.2 LUFS`，老版输出 `I:         -16.2 LUFS`。
**解法**：两种都认。
⚠ 注意 `loudnorm=print_format=summary` 在**测量**时不改变音频 ——
所以它量出的是**归一化后**的成片响度（−16.2 LUFS），不是源音频的响度。

### D5e. ⚠ 拼接时音频/视频要对齐到同一时间轴
每段单独拼（视频从黑场结束点截，音频从 0 取）→ 段内对齐靠黑场标记。
若整片改成"先拼视频再拼音频"，两边的时长必须完全一致，否则会累积漂移。

### D6. ⚠ bundle 落盘要用 `pg.on("response")`（§24）
在 `route` 回调里 `route.fetch()` 存文件实测**落盘 0 个**（异常被吞）。

### D8. ⚠ 音频要复用横屏已对齐的音轨
别从并行的旧音频目录取 —— **错位不报错**，只看得出来。

## E. 环境/工具层的坑

### E1. 🚨 `Path.home()` 在 agent 沙箱里被劫持
**症状**：`Path.home()` 返回沙箱的 home 目录，但凭据文件在另一个位置 → 静默拿不到 key。
**解法**：用**优先级链**而不是单一路径 —— `$TUTORIAL_ENV_FILE` → `$AGENT_ENV_FILE`
→ `$AGENT_HOME/.env` → 真实家目录的 `~/.env`（实现见 `scripts/agentenv.py`）。
⚠ **shell 里也一样**：`$HOME` 可能被劫持成沙箱 home → 找不到文件。
更稳的做法：从 PATH 上的 `python3` 真实路径**反推**家目录（`agentenv.real_home()`）。

### E1a. 🚨 依赖常在某个 venv 里，系统 python3 没有
**症状**：install.sh 报「playwright 未安装」，但明明装过。
**根因**：`python3` 是系统的 3.9，包装在 `venv/` 里（3.11）。
**解法**：脚本里**探测解释器** —— 依次试 `$TUTORIAL_PYTHON` → `$PY`
→ `$AGENT_HOME` 下的各种 venv 布局 → `python3`，
用第一个能 `import playwright` 的。
⚠ 只在终端里手动跑时无所谓，但**打包给别人的 skill 必须自己探测** —— 别人没有你的 venv。

### E2. 🚨 别用正则读 .env 的值
**症状**：`re.search(r'^KEY=(.+)$', env)` 这类形态会被密钥脱敏规则误判，
把源码里的正则打码成 `=***` → **SyntaxError**，而且很难看出是自己写坏了。
**解法**：逐行 `split('=', 1)` 解析。

### E3. 🚨 MiniMax TTS 返回的是 **hex 不是 base64**
**症状**：用 `base64.b64decode()` 解 → 得到一个「长得像 mp3 但 ffprobe 报
Invalid data」的坏文件，**而且不报错** → 后面合成时才炸，极难定位。
**解法**：`binascii.unhexlify()`。

### E4. 🚨 `record_video` 需要**完整 chromium**
headless_shell 不支持 screencast。装：`playwright install chromium`（三个组件）。

### E5. ⚠ 别用 `for c in "ABCDEFGH"` 生成列表
单字母 → symbol 丢前缀。同 C2。

### E6. ⚠ 退出码别放在管道后面取
`python check.py . | head` 之后 `$?` 拿到的是 `head` 的退出码（永远 0）。
用 `${PIPESTATUS[0]}`。

## F. 验收产物本身的坑

### F1. 🚨 验收要吃**归档后的交付物**，不是 /tmp 的中间产物
**症状**：中间产物和归档不一致（重录后 /tmp 更新、归档还是旧的）。
**解法**：验收脚本的输入路径指向**归档目录里的 mp4**；
先 `md5` 核对 raw_segments 与 /tmp 一致，再对归档 mp4 抽帧。

### F2. 🚨 别用另一个脚本的通过结果给成片背书
= A1。同源问题，但值得再说一次，因为它是最容易犯、代价最大的。

### F3. ⚠ 验证「修复生效」要断言，不能靠肉眼看
单元测试通过 ≠ 路由生效。必须在浏览器里断言 API before/after 真的变了。

### F4. ⚠ 视觉模型「列举」而不是「判断」
它能看出「这里有个数字」，但判不出「这个数字敏不敏感」。
提问写成「列出你看到的所有中文名词和所有数字」，然后**你来判这份清单**。
⚠ 反例：它会把「超时(分钟) 3」读成「超时品种 3」—— **视觉模型也会读错**，
报出来的「疑似 bug」要回源码核对再改。

### F5. 🚨🚨 验收必须**检测字幕是否存在** —— OCR 盲扫查不出来
**症状**：成片没有字幕，但规格/时长/响度/OCR 泄漏盲扫**全部通过**（见 D2e）。
**根因**：OCR 盲扫是找「不该出现的词」，**找不到字幕这种「该出现却没出现」的东西**。
画面里界面文字照常被读出来 → 一切正常。
**解法**：用**像素**检测字幕 —— 字幕是纯白字(255,255,255)+黑描边，铺在画面底部，
统计底部条带里的近白像素数即可判断该帧有没有字幕：
```python
box = im.crop((int(w*0.10), int(h*0.15), int(w*0.90), h))   # 中间80%宽, 去顶部15%
white = sum(1 for y in range(h2) for x in range(w2)
            if px[x,y][0]>225 and px[x,y][1]>225 and px[x,y][2]>225)
有字幕 = white > 150
```
`verify.py` 的阶段【4. 字幕覆盖率】已经实现，阈值：<90% 判失败，<97% 警告。
**自检**（每次交付前必跑）：
```bash
ffprobe -v error -select_streams v -show_entries stream=index -of csv=p=0 成片.mp4   # 必须1行
python scripts/verify.py --config project.json --video 成片.mp4 --amplify            # 阶段4
```
⚠ 别用「抽 3 帧用 vision 看有没有字幕」代替 —— 段落间隙本来就没字幕，
抽帧很可能全抽在空隙上，误判成"有字幕"或"没字幕"。**要全片扫。**

## G. 视觉层 / 节奏的坑（录屏类视频专属）

> 这一组是**录屏天生是死画面**引出的。
> 实测帧差：改造前变化强度 0.88、最长静止段 15s、静止占比 76%；
> 加视觉层后 4.76 / 1s / 2.0%。

### G1. 🚨🚨 `-t` 放在 `-i` 前面是**输入选项**，会只限制音频那一路
**症状**：段落实际时长比 `content` 长 1.3s（期望 19.33s，实际 20.64s）。
**根因**：`ffmpeg -ss X -i seg.webm -t 19.33 -i wav` 里的 `-t` 在第二个 `-i` 之前
→ 它是**输入选项**，只限制**后面那个输入(wav)**的读取时长，视频那路完全不受限。
**后果（连锁爆炸）**：
1. 段尾多出 1.3s 没有字幕 → 字幕覆盖率掉到 74%
2. **所有时间轴全部错位** —— 标题卡、高亮框、字幕统统偏移
3. 验收脚本会**误报"成片没有字幕"** → 白排查一轮
**解法**：`-t` 放**命令末尾**（输出选项）+ `[1:a]apad[apada]` 补静音：
```python
cmd += ["-filter_complex", fc + ";[1:a]apad[apada]", "-map", "[v]", "-map", "[apada]",
        "-c:v", "libx264", ..., "-t", f"{content:.3f}", out]
```
**自检**：`ffprobe -show_entries format=duration` 每段都应精确等于 `content`。

### G2. 🚨🚨 `-map` 的**顺序**决定输出流顺序，concat 按 index 对齐
**症状**：concat 报 exit 69 / "Error opening input file" 之类看不懂的错。
**根因**：段落文件里 `-map 1:a:0` 写在 `-map [v]` **前面** → 段落的**流 0 是音频**；
标题卡的**流 0 是视频** → concat demuxer 按 index 拼 → 格式不匹配。
**解法**：**视频的 -map 必须在音频前面**。concat demuxer 不会重排流。

### G3. 🚨🚨 音频必须**转成立体声**才能 concat
TTS 出的 mp3 是**单声道**，标题卡的静音是**立体声** → 声道数不一致 → 混流失败。
解法：`-c:a aac -b:a 192k -ar 48000 -ac 2`（**所有**分段统一）。

### G4. 🚨🚨 concat 时音频**不能 `-c copy`**
标题卡的静音 AAC 与段落的旁白 AAC **extradata 不同** → copy 出流损坏的音频
（`Decode error rate 0.865 exceeds maximum 0.666667`）→ 整条链失败。
解法：`-c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2`（视频 copy，音频重编码）。

### G5. 🚨🚨 `-map` 引用的输入下标必须**严格等于 `-i` 的添加顺序**
**症状**：高亮框没画出来 + 大段字幕丢失（覆盖率 79%）。
**根因**：字幕 PNG 先加（占 2..2+S-1）、高亮框后加（占 2+S..），
但滤镜链里高亮框从下标 **2** 开始引用 → **高亮框指向了字幕 PNG，字幕指向了高亮框**。
**解法**：显式算 `sub_base = 2` / `hl_base = 2 + len(pngs)`，**加 -i 的顺序 = 引用的顺序**。

### G6. 🚨🚨 推镜会把画面边缘内容**裁掉** —— 标注框/标签牌必须留安全区
**症状**：顶栏数字(y≈97)的高亮框，标签牌放在框上方(y≈46) → 推镜一漂，
**标签牌被裁出画面**，观众只看到一个没有标签的框。
**根因**：推镜 = 放大 Z 倍后裁一个 WxH 窗口漂移。原图坐标里只有
`y ∈ [H*(Z-1)/Z, H/Z]` 这一带**任何时刻都在画面内**。
**解法**：安全边距 = `H*(Z-1)/Z`（**不是** `H*(Z-1)/2` —— 那是放大图上的像素），
标签牌按 **上→下→右→左** 挑第一个完整落在安全区里的位置。

### G7. 🚨🚨 高亮框必须在**推镜之前** overlay
内容被推镜缩放平移后，同一张框 PNG 的像素位置就对不上目标了。
→ 顺序必须是：`0:v → 高亮框overlay → push → 字幕overlay`
（高亮框跟着内容一起被推；字幕是屏幕层，不该跟着被推）。

### G8. 🚨🚨 macOS Vision OCR 对**小字**在原生分辨率下会读成乱码
**症状**：同一帧里「总权益 1,020,518.26」用 1920×1080 读不出来，用 3840×2160 就读得出。
**解法**：`locate_text()` 先放大 2× 做 OCR，bbox 再**除回 scale** 换算成原图坐标。
⚠ 同理，验收读数字也必须 `--amplify`（见 F3）。

### G9. 🚨🚨 标题卡是**故意没有字幕**的 —— 覆盖率必须排除它
标题卡（静音章节卡）本来就不带字幕 → 按"全片每帧都该有字幕"算 → 覆盖率必然 ~75%
→ **误报"成片没有字幕"**。
解法：compose 输出 `timeline.json` 标出标题卡区间，verify 读它并排除。

### G10. 🚨 高亮框**定位不到**必须 fail loud，绝不能静默跳过
找不到目标文字 → 静默跳过 → 交付物看着正常但其实没有框（和 D2e 字幕是同一类病）。
compose.py 现在直接 `sys.exit` 报错。

### G11. 推镜**不要用 zoompan**
`zoompan` 的 d / fps / 时长三者关系极易错（实测把 20s 的段拉成 60s）。
用 `scale=iw*Z:ih*Z` + `crop=W:H:x='...sin(t/...)':y='...'` → 时长天然正确。

### G12. 高亮框的"章节配色"来自模块 —— 不是所有框都是青色
一个模块一个颜色（工作台青/数据蓝/实验室玫红/历史橙/工具紫/交易绿）。
好处：观众靠颜色定位章节。**验收时别按"应该是青色"去找框**。

### G13. 判断画面节奏**用帧差量化**，别凭感觉
`scripts/pace.py` 输出：变化强度(帧差均值)、变化帧/分钟、最长静止段、静止占比。
目标区间（录屏类）：强度 ≥3.0、变化帧 ≥30/分、最长静止 ≤6s、静止占比 ≤25%。
参考值：技术开源视频 89s 强度 19.35；ComfyUI 整合包 1210s 强度 6.21。

### G14. 🚨🚨 帧数必须取整 —— 否则 concat 留半帧空洞，容器推断成 50fps
**症状**：成片 `r_frame_rate=50/1`，但实际是 25fps；PTS 间隔在 0.04/0.08 之间跳。
**根因**：容器时长 ≠ 帧数/fps 时会留**半帧空洞**：
    duration=1.9s × 25fps = 47.5 帧 → 实际存 47 帧，但容器写 1.9s
    concat demuxer 按**容器时长**算下一段的起始偏移 → 每段后面留一个空洞
    → PTS 出现 0.08s 跳变 → 容器推断出 50/1（实际 25）
    → 部分播放器/剪辑软件会**错帧**。
**解法**：视频 `-frames:v N`、音频 `-t N/fps`，两者严格相等：
```python
frames = max(1, int(round(duration * fps)))
exact  = frames / float(fps)
cmd += ["-frames:v", str(frames), "-r", str(fps), "-t", f"{exact:.3f}", out]
```
⚠ **时间轴也要用 exact 值**（`timeline.json`），否则标题卡区间起止全偏
→ 验收排除错位置。
**自检**（交付前必跑，判定"无空洞"）：
```bash
ffprobe -v error -select_streams v -show_entries frame=pts_time -of csv=p=0 成片.mp4 \
 | tr -d ',' | python3 -c "
import sys; from collections import Counter
v=[float(x) for x in sys.stdin if x.strip()]
d=[round(v[i+1]-v[i],5) for i in range(len(v)-1)]
print(Counter(d).most_common(3))"    # 期望: 只有一个间隔值
```

### G15. 🚨 高亮框"框住了目标"要**客观验证**，不能靠看缩略图
**症状**：肉眼在 contact sheet 上根本看不出框准不准（缩略图看不清小字），
容易得出"框好像没画出来"的错误结论，或反过来"看着有框就当对了"。
**根因**：框的位置是**算出来的**，不是靠看。
**解法（决定性验收法）**：在成片里**先检测框的实际像素位置**，再 OCR 框内区域：
```python
# ① 用框的**精确 RGB**(如 #00e5ff) 紧公差匹配 → 只命中描边，不会命中 UI 自身的涨跌红绿
#    ⚠ 别用"高饱和度"来找框 → 数据页的红绿涨跌色会被一起命中 → 框位算成整屏
# ② 拿到框的 bbox → 往里缩几像素 → 裁出**框内部**区域 → 放大 2× 后 OCR
# ③ 框内 OCR 必须读到**目标文字** → 才算"框住了目标"
```
⚠ 数字归一化时**两边都要**去掉 `, . % -`：
    needle '1,020,518.26' → '102051826'；OCR '1,020,518.26' → '1020000.00'
    只归一化一边 → 永不相等 → 假失败。
⚠ **章节配色是按模块来的**，别按"应该是青色"去找框
（工作台青/数据蓝/实验室玫红/历史橙/工具紫/交易绿）。

## 第二轮: 字幕对轴 / 片头片尾 / 配乐 (v6)

### G16. 🚨 字幕时间**不能按字数摊** —— 必须用 ASR 强制对齐
**症状**：字幕整体比人声慢半拍，越到片尾偏得越多（每段偏 0.3~1.5s，累积能偏好几秒）。
**根因**：老方案按 `len(句)/总字数` 比例摊到整段 —— 这是**猜的**。TTS 语速不均匀（停顿/语速/句长都不同）。
**解法**：`asr_align.py` → difflib 把 ASR 字符序列与脚本字符序列对齐，
**时间取自 ASR，文字取自脚本原文**（零错字）。
⚠ ASR 中文同音字错很多（终端→中端、这一屏→这一瓶、合成→审查、全废→权费），
   所以**绝不能直接用 ASR 的识别文本当字幕**。

### G17. 🚨 对齐轴里**没有标点** —— 切句必须用脚本原文的标点
**症状**：按对齐轴字符切句 → 一个标点都找不到 → 整段变成一条字幕（8 段 → 只有 8 条）。
**根因**：`asr_align.py` 建轴时把标点全过滤了（ASR 输出本来就没标点）。
**解法**：用**脚本原文**的标点切句，再把每个字映射到对齐轴索引（去标点后两个序列一一对应）。
⚠ 切条要**一次成型**（单向扫描 + 断点规则），不要"先切句再切子句再合并" ——
   两次切分之间用字数重新对齐会**漏字**（实测 seg0 丢了整段「先说清楚：它不是一个成品软件，是」）。

### G18. 🚨 配乐**必须闪避旁白**，否则观众听不清解说
**解法**：`sidechaincompress`，旁白当触发源：
```
[1:a]...volume=-13dB[bg];
[0:a]asplit=2[va][sc];
[bg][sc]sidechaincompress=threshold=0.02:ratio=12:attack=8:release=350[bgd];
[va][bgd]amix=inputs=2:duration=first[a]
```
⚠ **attack 要快**（8ms），否则旁白第一个字被盖。
⚠ 混完**必须再做 loudnorm** —— 只用 alimiter 实测只有 -35.3 LUFS（目标 -16）。

### G19. 🚨🚨 串联两个 `atrim` 会让配乐**末尾凭空消失**
**症状**：配乐只输出 202.13s（应为 210.13s），末尾 8 秒是空的 → 片尾没配乐（实测 -41dB）。
**根因**：`atrim=start=8,aloop=...,atrim=0:210.13` —— 第二个 atrim 的 `end` 是相对
**原始输入流**算的，不是相对前一个 atrim 之后的流 → 两次裁剪叠加，长度错乱。
**解法**：**单个 atrim** 表达区间：`atrim=start=OFFSET:end=OFFSET+总长`，
循环交给输入选项 `-stream_loop -1`（比 `aloop` 滤镜可靠）。
⚠ 另：配乐曲目**开头常是静音淡入**（594 号 0~6s 是 -90dB）→ 片头会没声音。
   必须配 `start_offset` 从响亮段开始。

### G21. 🚨🚨🚨 选配乐**不能只看频谱图** —— 用户原话"你配的那个是什么垃圾配乐！"
**症状**：成片配乐被用户直接骂"垃圾"。选曲时所有数值指标都"命中"
（饱满度 A / 段落起伏 B / 低频强度 C 三项全中），但听起来就是没劲。
**根因（两层，第二层更致命）**：
1. **频谱图根本回答不了"激不激情"** —— 高级 Corporate 配乐和真带劲电子乐，
   频谱长得几乎一样。频谱三项全中 = 数字好看，**不代表听感对**。
   ⚠ 更糟：当时的可视化脚本**低频面板渲染失败**（FFT 长度只有 hop_i=220 →
   频率分辨率 100Hz/bin → 20~200Hz 只有 1 个 bin）→ 低频永远显示"空"。
   **低频指标失真会直接误导排序**。修法：FFT 窗长必须远大于 hop
   （win=0.05s / hop=0.01s → 1102 vs 220 → 分辨率 20Hz）。
2. **候选池的 genre 本身就是错的** —— 池子只覆盖
   `epic/cinematic/technology/upbeat/trailer/dramatic`，
   **全是"电影感/企业科技"**，一条 techno/drum-and-bass/house/electronic 都没有。
   → 选出来的 594 号 genre 实测是 `cinematic + dramatic` → 听起来就是 corporate 励志。
   **在池子全是电影配乐的时候，任何"打分"都只是在电影配乐里挑最好听的那首。**
**解法（按优先级）**：
- **① genre 先筛**：`techno / drum-and-bass / house / electronic / trance / dubstep /
  breakbeat / funk / rock / hip-hop` 这类是"带劲"候选池；
  `cinematic / ambient / chillout / corporate` 直接排除（除非明确要电影感）。
  genre 是**元数据硬证据**，不需要模型判断。
- **② 用真模型"听"**（不是看图）：
  - `MIT/ast-finetuned-audioset-10-10-0.4593`（AST）→ 527 类 AudioSet 标签，
    出 `Techno / Drum and bass / Electronic music / Drum machine / Bass drum` 等。
  - `laion/clap-htsat-unfused`（CLAP）→ **零样本音频-文本匹配**，
    直接问 "energetic electronic with driving beat and build up" vs
    "boring generic corporate stock loop"，看 MARGIN（正负提示的相似度差）。
  - 本机可跑：`pip install torch --index-url https://download.pytorch.org/whl/cpu`
    + `transformers`，模型下载走 `HF_ENDPOINT=https://hf-mirror.com`
    （直连 huggingface.co 超时）。
- **③ 云端音频理解**：DashScope 的 `qwen3-omni-flash` / `qwen-omni-turbo` /
  `qwen-audio-turbo` 都能吃音频，但**都要单独开通**（实测 403 Model.AccessDenied）；
  OpenRouter 的音频模型（voxtral / gpt-audio / gemini-omni）在本账号下
  普遍 403 或地区不可用 → **别在这条路上耗时间**，本地 AST+CLAP 更稳。
- **④ 结构验证**：能量包络要有 build-up（后段能量显著高于前段）+ 明确的落点，
  不是"全程能量高位"（那叫墙纸音乐）。
**🚨 铁律**：**交付前必须真的"听"过**（用 AST/CLAP，或让用户听 3 首候选选）。
拿频谱指标当"我验证过了"= 用一个回答不了问题的工具给自己背书。

**实战数据（可复现）**：
- 候选池 301 首（93 旧 + 208 新增动感 genre），CLAP 全量打分。
- **594 号（我原来选的）CLAP margin = −0.0085 → 全池第 290/301**；
  AST 三个采样点分别读出 `Violin 0.24 + Church bell + Sad music`、
  `Ambient 0.11 + Scary music`、`New-age music` → **小提琴钟声悲情氛围**，
  跟"激情科技讲解"毫无关系。**用户骂得完全正确。**
- 最终选 **623 号**（mixkit id 623）：genre `house/bass/sports/technology`，
  AST 三点均 `House music / Disco / Dance music / Electronic music`，
  CLAP margin +0.34~+0.36 稳定，时长 288.7s（免循环），
  能量 0.62→0.75→0.76 有起伏（对比 594 号只有 13 次起伏 = 墙纸）。
- 成片验收：25/1 fps、PTS 间隔 5251 个全 0.04s（无空洞）、单视频流、
  −15.4 LUFS、字幕像素 md5 与旧版 5/5 一致（视频流 copy 零损失）、
  配乐实测片头 −23.6dB / 旁白段 −15.8~-19.2dB（闪避生效，人声不被盖）。

**⚠ transformers 5.x 的两个 API 变更**（写新脚本会撞）：
- `model.get_text_features(...)` / `get_audio_features(...)` 可能返回
  `BaseModelOutputWithPooling` 而不是 Tensor → 要取 `.pooler_output`。
- `processor(audios=...)` 已改名 `processor(audio=...)`（旧名报
  `You passed keyword argument 'audios' which is deprecated`）。

### G23. 🚨🚨🚨 分段动态配乐：**三个滤镜顺序错误会把设计全部压平**
用户要求："开头/正文/结尾音量和内容应该不同，而且口播声音应该大些"。
不是把整条音轨调个音量就完事 —— 是**三段各自用曲子的不同段落 + 不同音量 + 口播主导**。

**🔴 踩了 4 个坑，每个都是"改了参数但实测没变化"，必须逐段实测才发现：**

| # | 错误 | 症状 | 根因 | 修法 |
|---|---|---|---|---|
| ① | 终混末端过 `loudnorm` | 片头比正文只高 2.4dB，片尾反而低 3.1dB | loudnorm 是**整片一次性归一化** → 把精心设计的三段相对关系压平 | **loudnorm 只作用于口播轨**（单独归一化），终混末端只留 `alimiter` |
| ② | `sidechaincompress` 作用于整条音乐轨 | 正文最轻、片头片尾最响（与设计完全相反） | 片头/片尾无旁白 → 闪避不触发 → `makeup=1` 把音乐**往上抬**；正文有旁白 → 音乐被压 | **闪避只做正文段**，片头/片尾直通 |
| ③ | 分段长度按"片头时长"取 | 标题卡区（4.2~6.12s）**一片死寂** LUFS -42 | intro 音乐段取 4.2s、body 段 `adelay` 到 4.2s → 两段之间**有空档**，标题卡正好落在空档 | 按**时间轴**对齐：intro 音乐 0~6.12s（含片头+首张标题卡）/ body 6.12~205.48 / outro 205.48~210.08 |
| ④ | 用 `volume` 表达式做区间增益 | 标题卡抬升"没生效" | 表达式里的 `t` 是**该滤镜流自己的时间轴**（body 流 adelay 前从 0 起），换算成片绝对时间要减偏移 | 用**独立 volume 滤镜 + `enable='between(t,..)'`**（enable 用输出时间轴 = 绝对时间，无歧义） |

**✅ 正确做法（顺序很重要）**：
```
① 三段各取曲子不同位置(能量曲线挑高潮点) → atrim + volume + afade
② 用 adelay 把各段对齐到成片时间轴 → apad=whole_dur 补齐
③ 口播轨: loudnorm 单独归一化 + highpass → asplit 成 [va] + [sc]
④ 标题卡区间: 独立 volume + enable 区间 (相对 body 抬 +9dB)
⑤ 闪避只做正文段: [bg_body][sc]sidechaincompress
⑥ 三段音乐 amix → [bgmix]
⑦ 终混: [va][bgmix]amix weights=1 0.34 → alimiter (不再 loudnorm)
```
⚠ **闪避要在标题卡抬升之前**：闪避只压有旁白处，卡片区无旁白不触发 → 抬升不会被二次压回。

**🔴 验证方法（必须逐段实测，不能凭感觉）**：
- **导出"音乐贡献"轨**：同一张滤镜图，把口播权重置 **0** → 得到音乐在成片里的实际电平
  （比单独导 stem 诚实：含 amix 权重与 limiter 的影响）
- 按区间切文件测 LUFS：片头 / 各标题卡 / 各正文段 / 片尾
- 目标关系：**片头 > 片尾 > 标题卡 > 正文**（正文是垫底）
- 再用 AST 模型听混音后的音频（`Speech` 标签强度）验证口播是否真的清楚

**实测成果**：
- 音乐贡献：片头 -21.6 / 标题卡 -28.3 / 正文 -48.3 / 片尾 -24.3 LUFS
  （片头比正文 +26.7dB，片尾 +24.0dB，标题卡 +20.0dB）
- AST 听辨语音清晰度（4 个采样点）：旧版 0.22/0.38/0.18/0.04 → 新版 **0.69/0.58/0.61/0.12**

**⚠ ffmpeg 标签不能复用**：同一标签既进 amix 又要单独导出 → 必须 `asplit`，
但主渲染里 asplit 的另一支未连接 → ffmpeg 报 **exit 234**
（"Error binding filtergraph inputs/outputs: Invalid argument"）。
**修法：主图和 stem 图分别构建，不要在同一张图里分叉。**

### G24. 🚨 口播轨本身可能很轻 —— 实测出来才发现
**症状**：成片响度正常（-16 LUFS），但用户说"口播声音应该大些"。
**根因**：口播轨实测只有 **-31.9 LUFS / 峰值 -18.0 dBFS** —— 本身就很轻。
旧版靠 `loudnorm` 在终混末端整体归一化 → 音乐占大头，口播被压住。
**修法**：口播轨**单独** `loudnorm=I=-18:TP=-3` → 成为主导，再与音乐 amix。
⚠ 别以为"成片响度达标"就等于"口播清楚" —— **响度是整体指标，口播/音乐比例是另一个指标**。
必须分开量：① 口播轨 LUFS ② 音乐贡献 LUFS ③ 成片 LUFS。

### G25. 🚨🚨🚨 「片头无旁白」不是通用前提 —— 照搬会盖死开场白
**症状**：开场 20 秒的解说要么听不清(AST Speech 0.18)，要么音乐被压得跟正文一样平(层次感全失)。
**根因**：G23/G24 的配乐方案默认「片头/片尾无旁白 → 直通 + 大增益」。
v6 成立（片头 4.2s 纯音乐）。但 **v9 的 intro 段是 0~24.36s 的「开场」，整整 23 秒都有旁白**。
照搬「片头直通 + -4dB」→ **音乐直接盖死开场白**，AST Speech 实测只剩 0.18。

**修法**：
1. **先确认每段有没有旁白**，再决定闪避范围。有旁白的段一律要闪避。
2. 闪避参数**分段设**（body 强 / intro·outro 弱），否则三段都被压成同一层，段落氛围全丢。
3. 增益和闪避强度是**此消彼长**的，必须两个指标一起量：

| 版本 | intro 增益 | 闪避 | AST Speech | intro 音乐比正文高 |
|---|---|---|---|---|
| mix1 | -4dB | 直通 | **0.18** ❌ 听不清 | +25dB |
| mix2 | -14dB | 统一 | 0.476 ✓ | **+4.7dB** ❌ 太平 |
| mix3 | -8dB | 分段(弱) | 0.32~0.43 ⚠️ | +17.6dB |
| **mix4** | **-12.5dB** | **分段(中)** | **0.345~0.454** ✓ | **+12.3dB** ✓ |

→ 调参时**不要只看一个指标**。AST Speech ≥ 0.3 且「片头音乐比正文高 ≥ 12dB」才算同时达标。

### G26. 🚨🚨🚨 中文渲染成豆腐块：**四个独立的坑叠在一起**，而且**全部不报错**
**症状**：PIL 画的中文全变成空心方框（缺字豆腐块），只有英文/数字正常。
**根因不是一个，是四个**，且每一个都**静默失败**（不抛异常、不报错）：

| # | 坑 | 机制 | 症状 |
|---|---|---|---|
| ① | **字体路径传成了函数** | `F = F9.F`（F 是**函数**），写 `F(F, 25)` → `ImageFont.truetype(<函数对象>, 25)` 抛 `AttributeError` → 被 `except: return ImageFont.load_default()` **吞掉** → 默认位图字体**没有汉字字形** | 满屏方框，**零报错** |
| ② | **Menlo 只有拉丁字形** | `Menlo.ttc` 是纯英文等宽体，拿它画中文 → 每字一个方框 | 同上 |
| ③ | **.ttc 的 index 选错** | `STHeiti Light.ttc` 是**字体集合**：index 0 = Heiti **TC**(繁体)，index 1 = Heiti **SC**(简体)。PIL 默认取 index 0 → 用繁体字形画简体字，部分字形不对 | 字能显示但字形怪 |
| ④ | **符号字形缺失** | STHeiti **没有 `✓`**（U+2713），有 `√`（U+221A）。Menlo 的 index 0 才是 Regular（1=Bold）→ **不能对所有 .ttc 一律 index=1** | 单个符号变方框 |

**修法**：
```python
def F(path, size):
    try:
        if "STHeiti" in path:                      # ① 只对中文字体指定 index
            return ImageFont.truetype(path, size, index=1)   # ③ SC 简体
        return ImageFont.truetype(path, size)     # Menlo 等走默认 index 0
    except Exception:
        return ImageFont.load_default()            # ⚠ 这里会把①的错吞掉 → 见下面的断言
```
**防呆**：加一条断言，杜绝①复发 ——
```python
assert isinstance(font_path, str), f"字体路径必须是 str, 收到 {type(font_path)}"
```
**自动选字体**（中文走黑体、纯 ASCII 走等宽，保住代码块的等宽观感）：
```python
def _has_cjk(s):
    return any("一" <= ch <= "鿿" or "　" <= ch <= "〿"
               or "＀" <= ch <= "￯" for ch in s)

def FM(s, size):
    return F(F_BOLD if _has_cjk(s) else F_MONO, size)
```

**🚨🚨 最贵的坑不是字体，是「诊断错方向」**：视觉模型看到方框就报「字体缺字」，
于是我去查「字体装没装 / 是不是繁体」——**全查错了**。真实主因是
**字号太小**（25px 在 1080p 全图里太小，缩略后笔画糊成一团，**看起来像方框**）。
→ **决定性诊断动作 = 对照渲染**：用**同一个字体、同一个字号、同一段文字**在纯色底上
单独渲染一张图，和实际帧逐像素对比。
   - 对照图正常 + 实际帧是方框 → 真是字体问题
   - 对照图也糊 → **字号问题**，放大字号即可
   这一步把排查时间从「查错方向几十轮」压到一次。
   ⚠ 视觉模型报「方框/乱码」时，**先怀疑字号，再怀疑字体**。

**字号下限**（1080p 横屏 B 站）：正文 ≥26px、说明 ≥24px、代码 ≥21px。
原 20~25px 在平台二次压缩后糊掉 → 一律提到 26~30px。
**放大字号必须同步缩短文案**（30px 时每行最多 16 字），否则溢出卡片。
改完**逐张视觉复核**，确认没有溢出/重叠。

**自检工具**：`scripts/check_font.py`（列出所有候选字体能否渲染中文 + .ttc index + 字号下限）。

### G27. 🚨🚨🚨 段间帧间隔跳变：**四个坑叠在一起**，根治要「视频/音频分两条线 + 全程整数帧」
**症状**：成片 `r_frame_rate=25/1` 看着对，但**段落接缝处** PTS 间隔出现 0.08s 跳变
（v9 实测 7 处，正好是 8 段的 7 个接缝：23.38/53.08/87.60/114.01/152.23/198.32/224.22）。
→ 严重时容器会推断成 50fps（v6 的老坑 G14）。

**四个叠加的根因**（逐个剥才对，**只修一个不会变**）：

| # | 根因 | 机制 |
|---|---|---|
| ① | **AAC 编码器固定预滚** | AAC 音频起始 pts = **−0.021333s**（负数）。concat demuxer 按**音频**时间戳推算下一段偏移，视频却从 0 起 → **两条时间轴不一致** → 每个接缝跳一次 |
| ② | **`-shortest` 按较短流截断** | 旁白比视频短 0.01s → 段长少 0.01s → 8 段累计少 8 帧 → 全摊到接缝上 |
| ③ | **浮点容器时长对齐** | 每段 ±1 帧误差 → 误差全堆到接缝 |
| ④ | **`atrim` 用浮点秒数截音频** | `atrim=0:{nframes/fps:.3f}` 浮点除法比视频少半帧 → **音频先结束** → concat 滤镜按最短的截 → **视频丢帧**（v9 实测 seg06/seg07 各少 1 帧） |

**✅ 根治方案（三条一起上，缺一条就还会跳）**：
1. **视频与音频分两条线走**，最后才合并 —— 视频轨完全不受音频影响。
   ```python
   # 视频线：帧数完全由输入决定，滤镜链 concat，不用 concat demuxer
   fc.append("".join(f"[v{st}][a{st}]" for st in range(n))
             + f"concat=n={n}:v=1:a=1[cv][ca]")
   ```
2. **全程整数帧计算**，不用浮点容器时长：
   ```python
   frames = max(1, int(round(dur * fps)))     # 整数帧
   exact  = frames / float(fps)                # 只用于 -t 显示值
   ```
3. **音频用 `apad` 补足，不靠 `atrim` 切到浮点秒**；整段拼完后再 `apad=whole_dur` 对齐总长。

**验收（唯一可信的判据）**：
```bash
python scripts/check_video_integrity.py 成片.mp4   # 帧间隔项
```
期望：**所有间隔 == 1/fps**，min == max == 中位，异常 0 处。
⚠ **ffprobe 的 packet pts 必须先排序** —— B 帧重排 → 输出顺序 ≠ 显示顺序，
不排序会算出 −0.08s 这种假异常（本次就踩了）。
⚠ 只看容器报 `r_frame_rate=25/1` **不够** —— 跳变时容器仍可能报 25/1。

### G22. 🚨 候选池 genre 抓取要**限速 + 退避**，别把源站打挂
mixkit 抓太快 → `HTTP 429 Too Many Requests`。抓 genre 列表页时：
每个 genre 间隔 ≥1s，429 退避 4/8/12s 重试。
⚠ 直接并发 12 抓 345 个页面 → 全 429，一个都没抓到。

### G20. 🚨 验收脚本要排除的"无字幕区间"有**四种**
`title_card` / `intro` / `outro` / **段尾静音尾巴**。
⚠ 只排除 title_card → 覆盖率被误判成 87.6% → **误报"成片没有字幕"** → 白折腾一轮。
⚠ 段尾静音尾巴：段落视频比旁白长（留白用），旁白说完后画面还在但没字幕，

⚠ macOS Vision OCR **读不了字幕区裁剪图**（白字黑边叠在复杂界面上 → 全是乱码）。
   要判断字幕对不对轴，得靠**更强的视觉模型**读裁剪图。

## H. 系列化（多期）的坑

> 这一组来自 2026-11-23「v6 总体介绍之后还要做什么视频」的排期实战。
> 完整方法 → repo 的 `docs/series-planning.md`

### H1. 🚨 总介绍片之后**不要**继续做「模块介绍」
总片已把每个模块各露一面 + 埋了伏笔 → 它的角色是 **Trailer（栏目总片）**。
再做一遍模块介绍 = 浪费一期 + 观众流失。
→ 之后每期的单位 = **「一个真实问题 + 一屏实操 + 一个能自己验的数字」**。

### H2. 🚨 凭空列的选题拍的时候没素材 → 整期作废
排期前必须做一次**本机真实资产盘点**（一次 grep 批量查）：
可讲的模块/路由/接口清单 · 源码里自己承认的边界 · 你的笔记库(研究/教训/决策分区) ·
现有 tutorial 章节 · 引擎的 validation 套件。
**只保留背后有可验证文件/接口的选题。**

### H3. 💎 最好的选题藏在「代码里自己承认的边界」里
源码注释写着「这块还没做」（如限价撮合）→ 天然反常识 + 天然建立信任 + 天然合规。
**一期至少要有一处「我做不了 / 我否掉了什么」。**

### H4. 🚨 规划文档里的真实名称/业绩数字会顺着标题流出去
内部笔记文档可以带，**但对外的标题/切片必须删**。
公开对象名（公开的商品名等）≠ 策略泄漏；
**任何业绩数字（年化/胜率/回撤/夏普）必须删** —— 标题会被截图传播。
边界要在规划时就说清，别到出片前才问。

### H5. ⚠ 待拍板项要给「二选一 + 我的判断」，别开放式问
❌「下一期你想做什么？」
✅「EP2 做撮合层吗？**我的判断：做**，重点讲『底层做不了限价撮合』——
   承认边界比假装全能更能建立信任。」
判断要短、要敢下，理由一句。给用户拍板，不辩论。

### G28. 🚨🚨 AST 分类器**不能**用来判断"音乐是否盖住口播"
AST 对「音乐 + 人声」的混合段**天生偏向 Music**。
真实案例 (v9 定版): mix5 在 t=8s 测出 `Music 0.463 > Speech 0.336`，
看着像音乐盖死开场白 → 差点白改一版。
**实测带内 SNR (300–3400Hz 内纯口播 vs 纯音乐能量比) = +18.3 dB** → 口播压过音乐，毫无问题。
AST 的 Speech 分数只是"这段声音里像不像语音"的分类概率，**不是清晰度**。

✅ **判断掩蔽要用带内 SNR**（用 `silent.mp4` 的纯口播轨 和 `*_musiconly.wav` 纯音乐轨）：
```python
win = sr                      # 1.0s 窗, Hann 窗
freqs = np.fft.rfftfreq(win, 1.0/sr)
band = (freqs >= 300) & (freqs <= 3400)
ev = (np.abs(np.fft.rfft(voice_seg*hann))**2)[band].sum()
em = (np.abs(np.fft.rfft(music_seg*hann))**2)[band].sum()
snr_db = 10*np.log10(ev/em)   # >0 = 口播在人声带内压过音乐
```
⚠ 必须**排除口播本身静音的时刻**（换气/段间停顿，口播 RMS < −45dB），
否则会把"没人说话"误判成"音乐盖住"。
v9 实测基线: intro +8.0dB / body +21.3dB / outro +7.2dB。

✅ **终审用 whisper 转写对照（地面真值）**：
拿最差的几个点，把**成片音频**和**纯口播**分别转写，比 Jaccard 字符一致度。
v9 五个最差点一致度 0.90–1.00 → 口播全程清晰可懂。
差异只会是「它/他」「序列/虚烈」这类同音字，是 whisper 自身噪声，不是掩蔽。

### G29. 🚨🚨🚨 后台进程回执**延迟** → 旧版验证日志会盖掉新版结论
nohup + `&` 起的进程，回执通知**什么时候到不可控**。
案例 (v9): 收到 3 条 `mix2/mix3` 的回执，但那时磁盘上早已是 **mix5**。
如果直接读 `/tmp/v9_clarity3.log`（那份是 **mix3** 测的），会得出
"定版 t=8s 只有 0.321，口播不清" 的**错误结论**，白白返工。

✅ **验证日志必须和成片时间戳对齐**，别信文件名：
```bash
ls -lT /tmp/v9_*.log          # 各次 mix/验证 的真实时刻
ls -lT 成片.mp4                # 成片写出的时刻
# 成片写出时刻 > 所有被引用的验证日志时刻 → 测的才是当前成片
```
✅ **内容级签名核对**（比时间戳更硬）：mix 脚本会打印自己的设计值
（如 `intro: +10.8 dB`），重新量一遍当前文件的段落增益，**逐位比对**。
✅ **md5 比对源文件与交付副本**，防止旧副本被当成交付物。

### G30. 🚨 长旁白段配**静态图**是节奏灾难 —— 片头/片尾要上真动画
v9 首版 intro(24.4s) / outro(22.6s) 用 4 张静态 reveal 图 + zoompan 推镜硬撑。
问题: **配乐最满、旁白最长**的两段, 画面几乎不动 → 观众感觉"这图我盯了 20 秒"。
这两段恰恰是最该有动态的地方(观众还在, 注意力最集中)。

✅ **解法: 逐帧渲染动画, 帧序列直出 ffmpeg**(别落 PNG 磁盘, 直接 pipe):
```python
cmd = ["ffmpeg","-y","-f","rawvideo","-pixel_format","rgb24",
       "-video_size","1920x1080","-framerate","25","-i","-",
       "-c:v","libx264","-preset","medium","-crf","20","-pix_fmt","yuv420p",
       "-frames:v",str(n),"-t",f"{n/25:.6f}", out]
p = subprocess.Popen(cmd, stdin=subprocess.PIPE)
for im in frames: p.stdin.write(im.tobytes())
p.stdin.close(); p.wait()
```
✅ **PIL 画动画的关键技巧**:
- 文字**预渲染成 RGBA 精灵**再按 alpha 贴 → 每帧省一次字体渲染, 快 10 倍
- `im.paste(sprite,(x,y),mask)` 用 L 通道掩码 → 半透明边缘正确
- 淡入淡出走 `seg(t,a,b)` 进度函数, 配 `lerp(c1,c2,k)` 插值颜色

✅ **动态段接进 build 管线时的三个坑**(v9 实测踩过):
1. 动画片段帧数必须**精确等于** `content_frames` → 用 `-frames:v` 硬裁后
   **再 `ffprobe -count_frames` 验一次**, 不符就 exit(否则接缝又跳帧, 见 G27)
2. 动画片段必须**带静音音轨**(`anullsrc`), 否则下面 concat 滤镜引用 `[st:a]` 会失败
3. 单 part 的段**不能走 concat 滤镜**(要求 n≥2)→ 改 `[v0]null[cv];[a0]anull[ca]` 直通

✅ **动画里画曲线图的要点**:
- **图例必须有**, 否则观众不知道蓝线是均线、红绿是涨跌
- 配色遵循 A 股铁律: **涨=红 跌=绿**(屏幕 y 越小=价格越高 → 上涨段用红)
- 渐显折线 = 只画 `npts = len(v)*progress` 个点, 配移动光标 + 数值标签 + 进度条

✅ **卡片框必须跟文字一起淡入**:
框常驻、文字后出现 → 中间态是一张**空卡片**, 看着像渲染坏了(视觉模型会直接报"内容缺失")。
→ `if ka > 0:` 里面同时画框(fill/outline 都用 `lerp(BG, PANEL, ka)`)和文字。

⚠ **验收要点**: 抽帧要看**中间态**不只看首尾帧。
首尾帧完美、中间态是空卡片 → 观众看到的就是那个中间态。

### G31. 🚨 目录级脱敏检查会扫到**中间产物的路径文本**
`check_leak.py <目录>` 会递归扫目录里所有文本文件 → 命中的全是
`_list_all.txt` 里写的本机路径, 退出码 1, 但**跟成片画面无关**。
✅ **验收对象必须只放交付物**:
```bash
mkdir -p /tmp/v9_deliver && cp 成片.mp4 发布文案.md /tmp/v9_deliver/
check_leak.py /tmp/v9_deliver --quiet     # ✅ 干净
```

### G32. 🚨🚨🚨 章节名和画面标题栏**不同源** → 简介里的章节全错位
v9 的章节名有两套来源:
- `script_v9.json` 的 `title`  = **旁白脚本**的标题(「为什么自己写」「工程化」)
- `frames_v9_anim.py` 的 SECTIONS = **画面顶部标题栏**的标题(「整体架构」「终端界面」)

两者**顺序和名字都不一样**! 旧简介用的是 script 的 title →
抽帧一比对就发现 00:54 画面写「整体架构」而简介写「数据层」, 整整错位一格。

✅ **章节名必须以「画面顶部标题栏」为准** —— 观众在 B 站看到的就是那个。
用抽帧验证, 别靠推断:
```bash
for t in 0 24 54 90 117 156 203 230; do
  ffmpeg -y -ss $t -i 成片.mp4 -frames:v 1 -vf "crop=1920:96:0:0,scale=960:48" /tmp/ch_$t.png
done
ffmpeg -y -i /tmp/ch_0.png -i ... -filter_complex "[0][1]...vstack=inputs=8" /tmp/strip.png
# 然后用 vision 读这张条带, 逐行核对
```
✅ **校验脚本要自动比对**「简介章节名」vs「画面标题」, 别手改:
```python
hit = name in actual[i] or actual[i].startswith(name)   # 章节名是画面标题的简称
```

✅ **中英混排的章节表要按视觉宽度对齐**(中文字符算 2 格, 否则描述列参差):
```python
def w(s):
    return sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in s)
name_w = max(w(n) for _, n, _ in rows)
pad = " " * (name_w - w(name))
```

🚨 **简介里每条要点都必须能在旁白原文里找到依据** ——
写文案时容易顺手补上「视频里其实没讲」的内容(比如原稿写了「账本自洽检查」,
但那版旁白根本没提)。→ 写完用关键词回查:
```python
missing = [k for k in claim_keys if norm(k) not in norm(full_narration)]
```
⚠ **简介不能比视频多讲东西** —— 观众对着视频找不到出处 = 标题党, 也可能被审核当成夸大。

### G33. 🚨🚨🚨 「激昂」不是加音量 —— 靠**冲击 + 词间回弹**
用户说「片头片尾声音大点、激昂」时, 只提 GAIN 是不够的。实测三版后真正有效的三件事:

**① 段首「静默蓄势 → 冲击涌入」**
整段一条 `afade` 缓慢淡入 = "慢慢浮起来", 一点也不激昂。
→ 段首先**真静音**(不是渐弱) 0.6~0.9s 蓄势, 再用极陡斜坡(0.3~0.35s)涌入。
实测包络: 段首 −88dB → +0.1s 跳到 −22dB, **瞬时跳 84dB** = 观众能感觉到的"砰"。

❌ **不能用两个 `volume=enable=...` 串联**:
enable 关闭时**整个滤镜被跳过** → 音量回到 0dB(全段最大) → 完全错。
✅ 用**一条 volume + `eval=frame` 表达式**算完整包络:
```
volume='if(lt(t,0.9),0.000178, if(lt(t,1.25),(t-0.9)/0.35, 1))':eval=frame
```
(0.000178 ≈ −70dB)

**② 闪避 release 从 380ms 缩到 160ms → 词间回弹**
口播一停, 音乐**立刻**顶回来, 词与词之间有呼吸感。
380ms 时音乐一直被压着 → 听感"闷"。
→ 同时把 threshold 压低(0.05→0.02)、ratio 拉高(5→14)、attack 缩到 3ms:
  说话瞬间几乎听不见音乐, 词一停马上回来。
**这才是"激昂"该有的样子: 音乐在空隙里爆, 不是一直盖着。**
⚠ 副作用: 音乐顶得更高 → 口播可能被压 → 必须靠更强 ratio 补偿, 二者一起调。

**③ 片尾收束前先冲高**
线性淡出会显得"泄气"。→ 淡出前 1.2s 先抬 2.5dB(×1.19), 再收束 → 收得有张力。

⚠ **只加音量会把口播压死**: 第一版 intro 音乐 +4dB 后, t=20s 带内 SNR 从 +11.9dB 掉到 **+0.14dB**。

### G34. 🚨🚨 选 BGM 片段要看「人声带占用」, 不是只看激昂度
选源时容易只看"冲击/激昂度" → 选到**高频多、人声带能量大**的段 → 音乐占住 300-3400Hz → 压住旁白。
✅ 必须**两个维度一起看**(对候选段算 25s 窗口):
```
impact = F[55-120Hz] / F[20Hz+]     冲击(越大越"砰")
vband  = F[300-3400Hz] / F[20Hz+]   人声带占用(越小越不压旁白)
```
选**冲击高 + 人声带低**的。实测:
```
 26s  冲击 43.8%  人声带 10.9%   ← intro 最优
196s  冲击 42.3%  人声带 17.6%   ← outro 最优
231s  冲击 11.1%  人声带 55.2%   ← 旧 outro, 全曲人声带最密的段, 必须换
```
🚨 **曲子的尾段往往是"柔和人声带密集段"** → 用尾段做 outro 必然压旁白。
→ outro 要选曲子**前中段的高能区**, 不是尾段。
⚠ 三段取材点要**互不重叠**, 否则听到的是同一段旋律。

### G35. 🚨 whisper 转写一致度**必须归一化繁简**, 否则假警报
v10 验收时 whisper 给出 "成片=回測引擎怎麼寫" / "干声=回測引擎怎麼寫",
字符 Jaccard 只有 **0.433** → 误判「听不清」。
实际两段文字**完全对应**, 只是 whisper 输出了繁体、且少了个逗号。
✅ 判据要用 `difflib.SequenceMatcher` ratio + **繁简归一 + 去标点**:
```python
import unicodedata, difflib
def norm(s):
    s = unicodedata.normalize("NFKC", s)
    return "".join(c for c in s if "一" <= c <= "鿿" or c.isalnum())
# 再套一层常用繁简字映射表
ratio = difflib.SequenceMatcher(None, norm(a), norm(b)).ratio()
```
归一化后同一段从 0.433 → **0.964**。
⚠ **不要用字符集合 Jaccard** —— 标点/繁简/漏字都会让它崩。
⚠ 阈值: ratio > 0.85 = 清晰, 0.7~0.85 = 勉强。

### G36. 🚨 抽样验清晰度会**采到最差点**, 别拿它当均值
v10 用 7 个点抽样 intro 的带内 SNR → 均值 +1.05dB, 看起来"音乐压死"。
但按 0.5s 步长全扫 46 个点 → **均值 +10.19dB**, 抽样恰好采到了最差的几处。
✅ **清晰度必须全扫或密集采样**(≤0.5s 步长), 抽样只用于快速迭代。
⚠ 样本里口播 RMS < −42dB 的点是**换气/停顿**, 不能算作"被音乐掩蔽" → 要排除。

### G37. 🚨🚨🚨 用"频带能量占比%"挑 BGM 片段 = 被带宽骗了
v10 选 outro 时用「全文件 FFT 后统计 300–3400Hz 能量占总能量百分比」当指标,
结果 **所有候选都落在 40~52%**（含 intro 基准 40.1%）→ 看起来毫无区分度。
根因: **宽带音乐的幅度谱几乎是平的**, 占比 ≈ 该带宽 / 奈奎斯特带宽
= 3100 / 8000 = **38.75%**, **跟内容无关**, 只反映带宽本身。
✅ 正确做法: 算**功率密度**并做**等带宽归一**, 用相对宽带平均功率密度的 dB:
```python
X = np.fft.rfft(x); P = np.abs(X)**2 / len(x)
freqs = np.fft.rfftfreq(len(x), 1/16000)
avg_density = P.sum() / (freqs[-1] - freqs[0])   # 每 Hz 平均功率
band_density = P[(freqs>=lo)&(freqs<hi)].sum() / (hi-lo)
db = 10*np.log10(band_density / avg_density)
```
判据: **< 0dB = 人声带比平均频段安静**(可当BGM底); 0~3dB = 偏亮; >3dB = 人声带突出(会压旁白)。
实测同一首曲子: intro_26 = **−5.22dB**(最干净) / outro_196 = −3.59dB / outro_231(旧选) = **−0.14dB**(最脏)。
⚠ 用功率(|X|)不要用幅度本身, 且必须除以带宽 —— 不除带宽就退化成上面那个坏指标。

### G38. 🚨 AST 跑在**纯音乐片段**上, Speech=0.000 是正常的
v10 对 BGM 候选片段单独跑 AST, 五个候选 Speech 全是 0.000 / Music 0.869~0.918,
容易误读成"这些片段有人声"或"AST 判不了"。
真相: **候选 wav 里本来就没有人声**, 所以 Speech=0 恰恰说明标签正常。
AST 在这里的职责只有一个: **测"这段音乐有多猛"**(Music 分数 + 冲击类标签命中数)。
→ 它**测不出人声带占用**(那是 G37 的事), 两者**互补, 不能互相替代**。
✅ 选段要三维度交叉验证:
| 维度 | 工具 | 判据 |
|---|---|---|
| 激昂度 | AST Music 分 + 冲击类标签命中 | 4/4 标签命中 |
| 冲击瞬态 | 55–120Hz 功率密度 dB | 越高越有"砰" |
| 人声带占用 | 300–3400Hz 功率密度 dB | 越低越不压旁白 |
⚠ 三者结论**可能互相矛盾**(实测 outro_231 的 Music 最高 0.794 但冲击命中只有 2/4) → **以"冲击 + 不压旁白"为准, Music 分只作参考**。

### G39. 🚨🚨🚨 "一打开就是高潮" = **切入点要预滚到重拍前**, 不是切在拍点上
v11 做「片头一打开就是高潮」时踩的坑:
- 切在重拍落点(25.875s) → 前 250ms 音乐在**渐入**(−11.8 → −18.6 dBFS) → 开头是"浮起来", 不是高潮。
- 根因: **鼓组的 kick 是在落点才砸下的**, 落点前 200ms 是起音期。
✅ 正确做法: **切入点 = 落点 − 0.25s**, 让冲击正好砸在 t=0。
扫描 13 个重拍 × 8 种预滚 → **预滚 0.25s 是所有落点的共同最优**(10/13 命中)。
实测: 切 25.875s 首 100ms = −11.8dBFS(爬升) vs 切 25.625s 首 100ms = **−8.23dBFS**(满能量)。
选点要**三重验证**: 人声带 dB(最干净) / 冲击 dB(最高) / 首 100ms 满能量。
⚠ onset 检测用**谱通量**(spectral flux), 别用 RMS 差分。

### G40. 🚨🚨🚨 闪避会把片头音乐**压死** —— 旁白从 0.1s 就开始说话时必踩
现象: 混完的纯音乐轨前 1.5s 全是 **−44~−50dB**, 音乐像"断了"。
排查顺序(照着走, 别猜):
1. 抽**纯音乐轨**(口播权重 0)看是不是真断 → 排除成片混合的干扰
2. 单独跑 `[bgm]volume=...:eval=frame` 看滤镜本身对不对
3. 跑**完整滤镜链**(`atrim→volume→highpass→volume env→afade→apad`)看链路
4. 以上都正常 → 就是**闪避**压的
✅ 解法: **只门控触发信号 [sc]**, 让片头前 0.5~0.8s 旁白不触发闪避。
```python
# ⚠ 只能门控 [sc](asplit 的触发副本), 绝不能动 [va](真正的声音) → 否则旁白被静音
fc.append(f"[sc]volume='if(lt(t,{gate}),0,if(lt(t,{gate+r}),(t-{gate})/{r},1))'"
          f":eval=frame[scg]")
```
⚠ 门控用 **ramp** 而非硬切, 否则闪避突然咬合产生"咔"声。
⚠ [sc] 的 t 是**全局时间轴** —— intro 的 delay_ms=0 时全局 t == 局部 t, 门控才对得上。

### G41. 🚨🚨 带内 SNR 要**扣除音乐贡献**, 否则全是假警报
v11 验证 intro 时算出 SNR **−3~−7dB**(音乐比人声强), 差点误判"旁白被糊掉"。
根因: 那个 SNR 是「成片带内能量 / **干声**带内能量」, 但**成片里的旁白经过了 loudnorm 增益**
(干声 −25.85dBFS → 成片 −18 LUFS), 比值自然变成负数。
✅ 正确算法: 用 **musiconly 轨**反推音乐在成片里的贡献, 再算残差:
```python
mus = band(musiconly) * (BG_WEIGHT ** 2)     # musiconly 已含 amix 权重
voice = max(band(mix) - mus, 1e-12)
snr_db = 10 * np.log10(voice / mus)
```
实测修正后: 豁免无衰减 **+23.4dB** vs 豁免+衰减 **+32.5dB** → 差 9.1dB, 才看出衰减包络的价值。
⚠ **旁白/音乐比 > +20dB 就算旁白清晰**(不是看 SNR 绝对值)。

### G42. 🚨 "冲击"要**快速回落**, 不能全程满能量
v11 豁免闪避后, 音乐在片头 0.8s 全程满能量 → 旁白/音乐比只有 +23dB, 第一句被糊。
✅ 正确: 冲击 → **快速回落** → 垫底 → 闪避接管:
```python
# t=0 满能量(砰) → fall 秒内线性落到 -13dB(垫底) → gate 结束前恒定 → 闪避接管
env = (f"if(lt(t,{fall}),1+({dbv}-1)*(t/{fall}),"
       f"if(lt(t,{gate}),{dbv},"
       f"if(lt(t,{gate+r}),{dbv}+(1-{dbv})*(t-{gate})/{r},1)))")
```
实测: 旁白/音乐比 +23.4dB → **+32.5dB**, 提升 9.1dB, 而 t=0 仍是满能量冲击。
⚠ 衰减包络要作用在**音乐轨**(闪避输入端), 不是触发信号。
⚠ **量音乐包络必须看 musiconly 轨**, 看成片会被旁白主导而误判(成片 RMS 变化是旁白造成的)。

### G43. 🚨 whisper 转写相似度用**拼音序列**, 别用繁简映射表
v11 验收时 whisper 对同一段给出「成片=手搓的意义」「干声=手措的意義」→ ratio 只有 0.692,
差点误判"旁白糊了"。**繁简映射表不完整 → 漏一个就崩**, 且同音错字(手措/手搓)照样扣分。
✅ 正解: **转成拼音序列再比** —— 天然免疫繁简、同音错字、标点、空白:
```python
from pypinyin import lazy_pinyin, Style
def pinyin_seq(s):
    s = unicodedata.normalize("NFKC", s)
    out = []
    for p in lazy_pinyin(s, style=Style.NORMAL, errors=lambda x: x.lower()):
        p = "".join(c for c in p if c.isalnum())
        if p: out.append(p)
    return out
ratio = difflib.SequenceMatcher(None, pinyin_seq(a), pinyin_seq(b)).ratio()
```
⚠ pypinyin 只在 agent 自带的 venv 里(该 venv 也有 faster_whisper);
   另一个只装了 torch+transformers 的 venv **没有** faster_whisper/pypinyin。
   → 找 venv: `python -c "import pypinyin"` 逐个试, 别假设。
⚠ whisper `transcribe()` 返回的是 **generator**, 要 `"".join(s.text for s in segs)` 才能拼文本。
⚠ 窗口要**≥4s 且 beam_size=5**: 3s + beam_size=1 时同一段音频的转写会随机抖动
(实测同一段成片/干声, 用 3s/beam1 得到 ratio 0.250, 用 10s/beam5 两边完全一致) → **别拿抖动当音频问题**。

### G44. 🚨 脱敏扫描器扫 mp4 = 几百条**二进制假阳性**
**症状**：`check_leak.py 成片.mp4 --quiet` 报「❌ 有 584 处 BLOCK —— 不许发出去」，
命中全是「x2」「Ab」这类两字母碎片 + 一串乱码字节，看着像泄漏了内部代号。
**根因**：扫描器按**文本**找关键词，而 mp4 里是 H.264 压缩码流 —— 任意字节序列
都可能凑出「Ab」「Xy」这种形状。**跟画面内容零关系**。
✅ **解法（两条，一起上）**：
① **扫描对象只放文本交付物**（发布文案 / 简介 / 章节表）。成片的画面用**抽帧 OCR** 验，
   别把 mp4 丢给文本扫描器。
② 判定「是不是真回归」要**跟上一版已验收成片做基线对照**：
   同一条命令跑新旧两版 → 数量级相同（实测老版 585 / 新版 584）→ 是系统性假阳性；
   数量暴增或命中词变了 → 才是真泄漏。
⚠ **别因为扫描器报红就重做画面** —— 先跑老版本基线。
⚠ 目录级扫描同理（见 G31）：验收目录只放交付物，别丢 build 中间目录进去。

### G45. 🚨🚨 OCR 子进程崩了 → stdout 为空 → 误报「干净」
**症状**：抽 8 帧做敏感词扫描，结果「0 行 / ✅ 无敏感词命中」—— 但画面上明明写着字。
**根因**：调 macOS Vision 的子脚本 `python3 ocr.py frame.png`，它 import PyObjC 失败
（`ModuleNotFoundError: No module named 'Foundation'`）→ **异常写 stderr，stdout 空**；
外层只读 stdout、不看 returncode → 0 行被当成「这张帧没有文字」。
⚠ 这是 A7「扫描结果是干净的 = 可能什么都没扫到」的**具体形态**。
✅ **三道断言**：
① 子进程 `returncode == 0`，否则打印 stderr 并非 0 退出；
② 每帧 OCR 行数 > 阈值（空帧是异常，不是干净）；
③ **必须有已知有字的帧做阳性对照** —— 一帧都没读到 → 立刻判定工具坏了，别看结论。
⚠ **视觉模型(VLM)读帧是更稳的兜底**：让 VLM「列出你看到的全部中文词」，
再自己判这份清单（A7 的规矩：prompt 里一个候选词都不给）。
⚠ macOS Vision 只能读**整帧**（见 G20：读不了字幕区裁剪图），裁剪图要用更强的 VLM。

### H6. ⚠ 全系列要统一的三件事别每期重新设计
视觉（6 模块各一色 + 章节卡 + 框选 + 推镜 9s）/ 音频（口播主导 + 四段不同音量）/ 字幕（ASR 强制对齐）。
每期换的只有：文案、录屏、章节配色。**观众要能认出是同一个栏目。**

# 字幕管线 —— 旁白文案 → 切句 → 时间轴 → 烧录

**用途**：教程视频必须带字幕（用户定的规矩）。本文件是「怎么做字幕」的完整配方。

可复跑脚本 → skill `real-app-tutorial-video` 的 `scripts/subtitle.py` + `scripts/compose.py`。

## 0. 三条铁律（先看这个，能省掉两小时）

### 铁律一：字幕必须在**拼片阶段**烧，不能成片后再烧
成片后再烧 = **二次编码** → 整帧重压缩 → **顶栏那些小字被压糊**。

实测证据（同一个画面）：
- 无字幕版：整帧放大能读出 `−1,652.90`
- 二次编码后：**读不出来了**（顶栏裁图 md5 都变了）

→ 字幕画在底部，但二次编码影响**整帧**。

**正确做法**：在 compose 拼 `v{i}.mp4` 的时候就 overlay 进去，
后面 concat 和 loudnorm 都用 `-c:v copy`（不重编码）→ 顶栏像素与无字幕版**完全一致**。

```bash
# 自检: 顶栏像素必须一致
ffmpeg -ss 12 -i 带字幕.mp4 -frames:v 1 -vf "crop=800:60:250:0" a.png
ffmpeg -ss 12 -i 无字幕.mp4 -frames:v 1 -vf "crop=800:60:250:0" b.png
md5 -q a.png b.png     # 必须相同
```

### 铁律二：ffmpeg 可能**没有 libass** —— subtitles 滤镜根本不存在
Homebrew 的 ffmpeg 默认不编译 libass / libfreetype / fontconfig。

**症状**：`ffmpeg -vf subtitles=xxx.ass` 报
`No option name near 'xxx.ass'` / `Error parsing a filter description`。

**陷阱**：无引号 / 转义冒号 / 引号+转义，**三种写法报的是同一个错** ——
看起来像路径转义问题，其实是滤镜不存在，会一直调错方向。

**自检**：
```bash
ffmpeg -hide_banner -filters | grep -E "subtitles|drawtext"   # 空 = 没有
ffmpeg -version | grep enable-libass                          # 空 = 没有
```

**解法**：**用 PIL 自己渲染字幕成 PNG，再用 `overlay` 滤镜贴上去**。
`overlay` 是内置滤镜一定有，而且字体渲染更可控（描边/字号/位置随便调）。

### 铁律三：断句要在**标点处**，不能按字数硬折
按 20 字硬折会把词切两半：
```
先说清楚：它不是一个成品软件，是一个模块一个模块搭起来的。
  硬折 → 「…是一个模块」/「一个模块搭起来的。」  ← 视觉上像重复了「一个模块」
```

→ 切句时在**每个逗号/顿号处**切（不设长度下限，可读性优先于条数）
→ 折行时在**标点处**断，**标点优先于长度**
→ 合并过短碎片（避免「为什么？」孤零零一条）

⚠ 有些句子内部**就是没有标点**（「回测图表那块我故意留空」）→ 任何算法都会硬断。
**这种情况改文案，加个逗号：「回测图表那块，我故意留空。」**
→ **字幕断句不自然是文案问题，不要用算法硬凑。**

### 铁律四：🚨 标点**永远优先于长度** —— 死守「每行 ≤ max_chars」会拆词

**症状**：「一旦把趋势曲线和一堆参数摆在一起，人会先看曲线，再回头调参数，」
折成「…人会先」/「看曲线，…」→ **"先看"被拆开**。

**根因**：早期规则要求**两行都 ≤ max_chars(20)**，否则退回硬折。
这条句子标点在第 23 字处 → 23 > 20 被拒 → 退回硬折 → 拆词。

**解法**：在所有标点候选里挑**让最长行最短**的那个，
只要最长行 ≤ `max_chars*1.25`(25) 就接受。
（1920 宽 + 44px 字体，25 汉字约 1100px，**远放得下** ——
长度约束是为了**可读性**，不是宽度限制，别把它当宽度用。）

```python
cands = [i for i in range(1, len(s)) if s[i-1] in "，、,；;。"]
best, best_score = None, None
for i in cands:
    a, b = s[:i], s[i:]
    longest = max(len(a), len(b))
    if longest > max_chars * 1.25:
        continue
    score = (longest, abs(len(a) - len(b)))   # 先看最长行, 再看均衡度
    if best_score is None or score < best_score:
        best_score, best = score, i
```
⚠ 挑「离中点最近」的标点**不够好** —— 多个标点时它未必让两行最均衡。

### 铁律五：⚠ 切句阈值 = `max_chars*1.5`（30 字），不是 20 也不是 40

三个值都实测过：

| 阈值 | 条数 | 结果 |
|---|---|---|
| `max_chars*2` (40) | 47 | 太多长句要折行 → 拆词 |
| `max_chars` (20) | 68 | 几乎不折行，但字幕**闪太快**（2.75s/条）|
| **`max_chars*1.5` (30) | **58** | **平衡** —— 3.2s/条，基本单行或两行都在标点处 |

判断标准：**按「每分钟多少条」算阅读节奏**，不是按条数本身。
187 秒 / 58 条 ≈ 3.2 秒/条 ≈ 18.6 条/分钟 → 15-20 字的字幕读起来从容。

### 铁律六：🚨 字幕会被**静默跳过** —— 交付物根本没字幕，而所有验收都过

**症状**：交付的视频**完全没有字幕**，是用户发现的。

**诡异之处**：规格正常、时长正常、响度正常、OCR 泄漏盲扫正常、
顶栏像素 md5 与无字幕版**完全一致** —— **所有自动化验收全过**。

**根因**：
```python
script_path = pathlib.Path(cfg.get("script_path", "script.json"))
if sub_cfg.get("enabled", True) and script_path.exists():   # ← 找不到就跳过, 不报错!
```
`script_path` 是相对路径，且**相对 CWD** 解析。
归档目录里文案叫 `script4.json`，父目录才叫 `script.json` →
换个目录跑 compose → 找不到 → **字幕被整段丢弃**，流程 0 退出成功。

**解法**（三条一起上）：
```python
script_path = pathlib.Path(cfg.get("script_path", "script.json"))
if not script_path.is_absolute():
    script_path = pathlib.Path(a.config).resolve().parent / script_path   # 相对配置文件目录
if sub_cfg.get("enabled", True):
    if not script_path.exists():
        sys.exit("❌ 字幕已开启但找不到文案 ... —— 字幕必须烧进成片, 不能静默跳过")
```
**铁律：任何"可选特性"的开关，要么真的开，要么报错退出，绝不能静默降级。**

### 铁律七：🚨 有字幕时 `-map` 只能有**一条**视频流

```python
cmd += ["-map", "0:v:0", "-map", "1:a:0"]              # ← 原片
if pngs:
    cmd += ["-filter_complex", fc, "-map", f"[{prev}]"] # ← 字幕片
```
两条视频流 → 播放器默认放**第一条**（无字幕那条）→ 白烧。

```python
cmd += ["-map", "1:a:0"]
if pngs:
    cmd += ["-filter_complex", ";".join(fc), "-map", f"[{prev}]"]
else:
    cmd += ["-map", "0:v:0"]
```
**自检**：`ffprobe -v error -select_streams v -show_entries stream=index -of csv=p=0 成片.mp4`
→ 必须**只有 1 行**。

### 铁律八：⚠ 字幕铺到**语音结束**为止，不是段尾

段落视频比旁白长（`content = wav_dur + 0.9`，多留 0.9s 余量）。
- **按字数摊时**：按 `content` 分配且最后一条吃段尾（`seg_d = seg_total - t`）。
- **用 ASR 对齐时**：字幕时间**天然结束于语音结束**（`chars[-1].e`），
  段尾那 0.9s 留白**本来就没有字幕** —— 这是设计如此，不是缺陷。

⚠ **验收脚本要排除段尾静音尾巴**，否则覆盖率被误判：
实测 seg0 旁白 18.26s 结束、段落长 19.32s → 尾部 1.06s 无字幕。
从 `align.json` 读每段 `chars[-1].e` 才是旁白真正结束的时间。

⚠ 因此**字幕覆盖率天然到不了 100%** —— 语音有停顿，字幕就该跟着停。
v6 实测 93.8%（阈值 90%）。剩下的缺口是**语音停顿处的自然间隙**，不是缺字幕。

## 1. 时间轴：🚨 **必须用 ASR 强制对齐**，不能按字数比例分配

> ⚠ **本节在 v6 已被推翻重写。** 旧方案（按字数比例摊时间）实测**偏差可达 0.3~1.5s/段**，
> 累积到片尾能偏好几秒 —— 观众看到的是「字幕比人声慢半拍」。
> 旧文档曾写「实测偏差 < 0.3s」—— **那是错的**，不要信。旧方案对照保留在 §1.6。

### 1.1 为什么按字数比例是**猜的**

TTS 没返回逐句时间戳。MiniMax 的 `subtitle_enable=True` 确实能拿到 `subtitle_file`，
但返回的是**整个段落一条**（含 `time_begin`/`time_end`/`text_begin`/`text_end`），
**不是逐句** → 只能退回按字数摊：

```
句时长 = 该段旁白时长 × (该句字数 / 全段字数)     ← 假设语速恒定
```

这个假设**不成立**：TTS 语速随句长/停顿/标点/情绪变化。
同样 20 个字，「先说清楚：」后面有停顿，「成交明细」一气呵成 —— 差出半秒很正常。

**实测（v6）**：8 段共 178s 旁白，逐段比对对齐轴 vs 字数摊的结果，
**每段偏 0.3~1.5s，方向不固定**（有的早有的晚）。

### 1.2 正解：强制对齐（forced alignment）

**核心思想：时间取自 ASR，文字取自脚本原文。**

```bash
python scripts/asr_align.py --script script.json --audio-dir audio --out align.json
```

流程：
1. faster-whisper 出**逐词**时间戳（`word_timestamps=True`）→ 展开成逐字
2. difflib 把 ASR 字符序列与**脚本字符序列**对齐
3. 匹配上的字 → 时间取自 ASR；没匹配上的（ASR 漏字/错字）→ 用前后锚点**插值**
4. 输出 `align.json`：`{seg: {chars: [{c, s, e}], ratio}}`

`ratio` = 对齐率，低于 0.80 直接报错退出（ASR 与文案严重不符，不该出轴）。
v6 实测 8 段平均对齐率 **0.956**。

### 1.3 🚨 不能直接用 ASR 的识别文本当字幕

faster-whisper 中文**同音字错得很多**：

| 原文 | ASR 识别 |
|---|---|
| 终端 | 中端 |
| 这一屏 | 这一瓶 |
| 全程 | 源程 |
| 合成 | 审查 |
| 全废 | 权费 |
| 拼接 | 应接 |
| 树深 | 数身 |
| 留空 | 流空 |
| 答案 | 打案 |
| 浮窗 | 服装 |
| 手数 | 手术 |
| 止损 | 直损 |
| 止盈 | 指营 |

所以：**时间用 ASR 的，文字用脚本原文的**。这样既有精确时间轴，又零错字。

### 1.4 🚨 对齐轴里**没有标点** —— 切句必须用脚本原文的标点

`asr_align.py` 建轴时把标点全过滤了（ASR 输出本来就没标点，脚本的标点对不上 ASR 字符）。
→ 如果按对齐轴的字符切句，**一个标点都找不到** → 整段变成一条字幕。
   实测：8 段 → 只有 8 条（原来按字数摊是 55 条）。

**正确做法**：用**脚本原文的标点**切句，再把每个字映射到对齐轴索引
（脚本原文去标点后的字符序列，与对齐轴字符序列一一对应 —— 对齐率就是这个保证）。

### 1.5 🚨 切条要**一次成型**，不要"先切句再切子句再合并"

两次切分之间用「字数」重新对齐会**漏字**。实测 seg0 丢了整段
「先说清楚：它不是一个成品软件，是」。

**正确模型**：按原文顺序**单向扫描**，遇到标点就是断点，每个块记录
`(在去标点序列里的起止, 原文文字)`。块之间不重叠、不遗漏 → 拼起来必然等于原文。

断点规则：
- 句末标点（。！？；）→ 必断
- 逗号类（，、,:）→ 断，但只有当前块已够长（≥ `max_chars*0.5`）才断，
  否则并入下一块（避免「为什么？」这种孤条）
- 块长 > `max_chars*1.5` → 在最近的逗号处硬切，没有逗号就硬切

**自检（必做）**：拼起来的字幕文字必须 == 原文去标点后的文字。
```python
got  = "".join(t for _,_,t in cues[i])          # 字幕拼起来
norm = "".join(c for c in script[i]["text"] if c not in PUNCT)
assert got_normalized == norm                    # 不等就是漏字，必须修
```

### 1.6 旧方案（按字数摊）—— 只在没有对齐轴时兜底

配置里没有 `align_path`（或文件不存在）时才走这条路，
且 **compose 会打印警告**，不静默。

对齐轴版实测：**65 条字幕，8 段字数全部完整**（87/87、132/132、104/104…）零缺失，
标点保留，时间轴单调无异常。

## 2. 渲染（PIL）

```python
from PIL import Image, ImageDraw, ImageFont

im = Image.new("RGBA", (1920, 1080), (0, 0, 0, 0))   # 透明底
d = ImageDraw.Draw(im)
font = ImageFont.truetype("/System/Library/Fonts/PingFang.ttc", 44)
line_h = int(44 * 1.35)
y = 1080 - 60 - line_h * len(lines)                    # 底距 60px
for ln in lines:
    bb = d.textbbox((0, 0), ln, font=font)
    x = (1920 - (bb[2]-bb[0])) // 2
    for dx, dy in ((-2,0),(2,0),(0,-2),(0,2),(-2,-2),(2,2),(-2,2),(2,-2)):
        d.text((x+dx, y+dy), ln, font=font, fill=(0,0,0,235))   # 黑描边
    d.text((x, y), ln, font=font, fill=(255,255,255,255))      # 白字
    y += line_h
```

**样式要点**（深色 UI 录屏）：
- 白字 + **黑色描边**（8 向偏移）→ 亮背景上也能看清
- 底距 60px（1080 高）→ 距底边约 7-9%，**安全区**（平台/播放器 UI 会遮最底边）
- 字号 44px；每行 ≤ 20 汉字（实测最长行 22 字仍可读）
- 一次最多 2 行

⚠ 字体候选：`PingFang.ttc` → `STHeiti Medium.ttc` → `Hiragino Sans GB.ttc` → Noto CJK。
⚠ STHeiti **没有 emoji 字形** —— 字幕文案里别放 emoji。

## 3. 烧录（overlay，一次 filter_complex）

每条字幕渲染一张 PNG，然后串成一条链：

```
[0:v][1:v]overlay=0:0:enable='between(t,0.000,3.100)'[v0];
[v0][2:v]overlay=0:0:enable='between(t,3.100,8.720)'[v1];
...
```

⚠ **不要一条字幕调一次 ffmpeg**（37 条 = 37 次进程，慢到不可用）。
⚠ `enable='between(t,a,b)'` 的时间是**相对该段**的（因为拼片时每段单独处理）。

## 4. 验收

**字幕也是画面内容**，OCR 盲扫必须包含它 —— 扫的是**带字幕那版**。

⚠ **数字判读要两种读法都做**：
- 整帧放大（1920×1080 → 3840×2160）
- 区域裁剪（顶栏、明细区分别裁）

两者**各有盲区**：Vision OCR 的行聚类对输入布局敏感 ——
同一个画面，整帧放大能读出 `−1,652.90`，裁成顶栏细条就读不出；
反过来带字幕版整帧读不到。**数字取并集**。

⚠ 抽帧**不要抽第 0 帧**（编码器起始帧是黑的），用 `-ss N` 抽中间帧。

### 4b. 🚨 字幕覆盖率：必须**用像素检测**，OCR 盲扫查不出来

OCR 盲扫是找「**不该出现**的词」，**找不到「该出现却没出现」的东西**。
成片没有字幕时，画面里界面文字照常被读出 → 一切正常 → 报「✅ 零泄漏」。

**原理**：字幕是**纯白字**(255,255,255) + 黑描边，铺在画面底部。
统计底部条带里的近白像素数 → 有字幕的帧会明显偏多。

```python
box = im.crop((int(w*0.10), int(h*0.15), int(w*0.90), h))   # 中间80%宽, 去顶部15%
white = sum(1 for y in range(h2) for x in range(w2)
            if px[x,y][0]>225 and px[x,y][1]>225 and px[x,y][2]>225)
有字幕 = white > 150
```
`verify.py` 的阶段【4. 字幕覆盖率】已实现（阈值：<90% 判失败，<97% 警告）。

**⚠ 一定要跑阴性对照**，证明检测器真的会报警：
```bash
# 拿一段确定没有字幕的原片跑同一个检测器 → 必须是 0%
python -c "
import sys; sys.path.insert(0,'scripts')
from verify import subtitle_coverage
print(subtitle_coverage('原始分段.webm', '/tmp'))"    # 期望 (N, 0, [...])
```
本 session 实测：带字幕版 97.9%，无字幕原片 **0.0%** → 检测器可靠。

⚠ **别用「抽 3 帧用 vision 看有没有字幕」代替** —— 段落间隙本来就没字幕，
抽帧很可能全抽在空隙上，误判成「有字幕」或「没字幕」。**要全片扫。**

### 4c. 交付前两道必查

```bash
# ① 视频流必须只有 1 条(两条 = 播放器放第一条 = 可能放的是无字幕那条)
ffprobe -v error -select_streams v -show_entries stream=index -of csv=p=0 成片.mp4
# ② 阶段【4】字幕覆盖率
python scripts/verify.py --config project.json --video 成片.mp4 --amplify
```

**这两道是唯一能拦住「交付物缺功能」的自动化检查。**

### 4d. 🚨🚨 覆盖率必须排除**四种**无字幕区间

| 区间 | 为什么无字幕 |
|---|---|
| `title_card` | 章节卡是静音路标，故意压屏无字幕 |
| `intro` | 片头是纯图形开场，无字幕 |
| `outro` | 片尾是收尾卡片，无字幕 |
| **段尾静音尾巴** | 段落视频比旁白长，旁白说完后画面还在 |

⚠ **只排除 `title_card` 会把覆盖率误判成 87.6% → 误报「成片没有字幕」→ 白折腾一轮排查。**
段尾静音尾巴从 `align.json` 读每段 `chars[-1].e` 才是旁白真正结束的时间。

⚠ **覆盖率天然到不了 100%**（v6 实测 93.8%）——
语音有停顿，字幕就该跟着停。剩下的缺口是自然间隙，不是缺陷。

### 4e. 🚨 覆盖率只证明「有白字」，**不证明「字幕对得上语音」**

像素检测只能回答"字幕在不在画面上"，回答不了"字幕跟不跟得上人声"。
**内容级对轴验收必须单独做**：

```bash
# ① 抽帧 → 裁底部字幕带(只留字幕那一行, 避开界面元素)
ffmpeg -ss $T -i 成片.mp4 -frames:v 1 f.png
ffmpeg -i f.png -vf "crop=1920:100:0:930,scale=2880:150:flags=lanczos" c.png
# ② 交给视觉模型 OCR → 与对齐轴里该时刻应出现的文字比对
```

⚠ **macOS Vision 读不了这种裁剪图** —— 白字黑边叠在复杂界面上，
Vision 会把界面里的数字/英文当主体，读出一堆乱码（实测：
`LLM(B)10*X*AtJJJ•sJJSAChamp*nXX#llll*litOkenIAXfts`）。
**必须用更强的视觉模型**读裁剪图。

⚠ **裁剪区域要只留字幕那一行**（y≈930~1020）。裁太宽会把界面元素带进来，
OCR 主体就被带跑。

⚠ 抽样**每段 2 个点**（段内 30% / 65% 处），比对时取期望串前后各 3~4 字做**模糊匹配**
（OCR 个别字可能认错），匹配率 ≥50% 算过。

v6 实测：16 个检查点全部有字幕且与语音吻合。例如 t=82.34s 画面显示
「种群是每一代同时试多少个因子公式，」，正是该时刻语音内容。

## 5. 踩坑速查

| 症状 | 根因 | 解法 |
|---|---|---|
| `No option name near 'xxx.ass'` | ffmpeg 没 libass | PIL 渲染 + overlay |
| 加字幕后读不出 `−1,652.90` | 二次编码压糊顶栏 | 拼片阶段烧 + `-c:v copy` |
| **成片完全没有字幕，但所有验收都过** | **script_path 相对 CWD 解析失败 → 静默跳过** | **相对配置文件目录解析 + 找不到就 sys.exit** |
| **烧了字幕但播放器看不到** | **`-map 0:v:0` + `-map [vN]` → 两条视频流** | **有字幕时只 map 滤镜输出** |
| 字幕看起来像重复 | 按字数硬折 | 标点处断 + 改文案 |
| 字幕断在词中间（「…用的哪段行」/「情、」） | 死守「每行 ≤ max_chars」→ 退回硬折 | 标点优先于长度（≤1.25×） |
| 字幕闪太快 | 切句阈值太小 | 阈值取 `max_chars*1.5`，按「条/分钟」判断 |
| **字幕比人声慢半拍，越到片尾越偏** | **时间轴按字数摊 = 猜的** | **ASR 强制对齐（`asr_align.py`）** |
| **切句后整段变成一条字幕** | **对齐轴里没有标点 → 一个标点都找不到** | **用脚本原文的标点切句** |
| **切条后有字丢失** | **两次切分之间用字数重新对齐** | **单向扫描一次成型，不做二次合并** |
| 每段末尾 1 秒没字幕 | 段落比旁白长（留白） | 设计如此，验收时排除段尾静音尾巴 |
| OCR 盲扫说干净，但成片没字幕 | OCR 只找「不该出现的词」 | 像素级字幕覆盖率检测 + 阴性对照 |
| **覆盖率误报 87.6%「成片没字幕」** | **只排除了 title_card** | **要排除四种：title_card/intro/outro/段尾静音** |
| `UnboundLocalError: dur` | 循环变量 `dur` 遮蔽了 `dur()` 函数 | 改名 `seg_d` |
| 字幕太靠底被平台 UI 遮 | margin_v 太小 | 60-90px |
| 竖屏 | — | ❌ 永久废弃 |

## 6. 文案侧配合

字幕断句的根源常常在**文案**。写旁白时：
- 长句在逗号处自然断开，别把两个短句用「，」硬连
- 每句 ≤ 20 字最好，25 字以内也能排成 2 行
- 标点用全角（`，。；：？！`），断句算法按全角标点切
